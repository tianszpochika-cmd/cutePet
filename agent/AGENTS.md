# Agent 协作规范（纯 Agent 项目）

> 本项目由 AI Agent 作为主要执行者完成需求、设计、开发全流程。
> 所有 Agent 在本仓库工作时须遵守本文件。

## 1. 阶段纪律

- **阶段一（需求与设计）已完成**（2026-09-22：需求定稿含上线合规修订；设计 14 份文档产出）。
- **当前进入阶段二/三（选型与开发）**：技术选型与开发内容**只允许**写在 `docs/05-技术文档/`，禁止回流 `docs/01`（需求）与 `docs/02`（设计）。
- 开工以 `docs/05-技术文档/开发任务规划.md` 为准；其 §0 完成定义与 §5 无 Bug 出口准则不可降低。

## 2. 文档工作流

1. 动手写之前，先读 `README.md`、`docs/00-项目概述/`、`docs/01-需求文档/PRD-总纲.md`。
2. 遵守 `docs/04-规范与模板/文档规范.md`（状态头、版本、待定标注）。
3. 发现需求冲突 → 记入 `docs/04-规范与模板/评审记录.md` 待办，不擅自决定重大范围变更。
4. 废弃文档 → 移入 `archive/`，不直接删除。

## 3. 目录归属

| 内容类型 | 放置位置 |
|----------|----------|
| 做什么（需求） | docs/01-需求文档/ |
| 怎么呈现（设计） | docs/02-设计文档/ |
| 依据与调研 | docs/03-研究资料/ |
| 规范、模板、术语 | docs/04-规范与模板/ |
| Agent 工作流与提示词 | agent/ |
| 未来各端代码 | apps/<端名>/ （选型后启用） |
| 跨端共享 | packages/ （选型后启用） |

## 4. 代码目录约定（选型后生效，仅占位说明）

- `apps/web` — 用户端 Web
- `apps/site` — 官网
- `apps/admin` — 管理端
- `apps/mobile` — 移动端
- 目前这些目录**尚未创建**，待阶段二技术选型后再初始化。

## 5. 协作建议

- 一次 Agent 只负责一个边界清晰的任务（如「完成需求-宠物探索.md」）。
- 产出必须落在文件系统中（文档或代码），不只给对话结论。
- 完成任务后更新对应文档的状态头与里程碑勾选项。
