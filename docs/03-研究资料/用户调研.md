# 用户调研与假设验证计划

> 状态：草稿（计划已编写，尚未开展真实调研） · 版本：v1.0 · 更新日期：2026-09-22

## 1. 假设与反证

| 假设 | 研究问题 | 不成立时如何调整 |
|---|---|---|
| H1 照护记录存在持续价值 | 最近一次漏记/重复处理是什么，现用方法成本如何 | 改任务入口和记录步骤，不伪造提醒频次 |
| H2 家庭共享值得额外授权 | 谁主要照护，家人是否愿意加入，哪些信息不愿共享 | 优化默认只读与主动共享；保留个人使用完整性 |
| H3 提醒驱动复访 | 用户真实通知授权意愿、设备环境、实际发生频率 | 验证真实渠道与限制，不用站内消息冒充离站召回 |
| H4 同一人群需要其他模块 | 完成照护后何时查资讯、找场所、看评测 | 将相关内容作为可选任务，调整入口，不强迫串行浏览 |
| H5 投稿及活动供给可持续 | 首次投稿成本、审核反馈、机构名单处理是否可承担 | 改编辑/审核与运营流程，不靠惩罚普通退修保证质量 |

## 2. 招募与步骤

目标12–20位真实养宠者，至少4组共同照护家庭；覆盖新手/有经验者及不同设备。人数是招募目标，不能填作已完成访谈数。

1. 经受访者同意记录访谈，收集既有流程与具体最近案例；不诱导对假设表示赞同。
2. 从真实任务原型完成建档、未来提醒、家人处理、退出、首次投稿、活动报名及取消；记录帮助次数、耗时、错误与放弃原因。
3. 连续28天试用，按K指标观察；低频照护任务另看60–90天成熟窗口，尊重退出与撤回。
4. 每周按问题严重度修订并保留版本；同任务修改前后对比，样本不足不作统计显著性结论。

## 3. 记录模板与验收

每次记录受访者匿名编号、用户分层、设备、任务及原型版本、是否独立成功、错误/求助、原话、研究者解释、同意与保留期限。事实和解释分开；影像/联系方式不进入公开仓库。

样例任务及暂定内部出口见 [指标口径](../01-需求文档/需求-指标与验收口径.md) §5。结果表当前为空；没有访谈来源的用户需求仅标假设。
