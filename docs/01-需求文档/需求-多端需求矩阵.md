## 3. 各端关键要求

### 3.1 移动端（第一版全量）
- 与 Web 功能对齐：消费、记录、投稿、探索、家庭共享全部可完成。
- 平台能力诉求：推送通知（提醒触达的生命线）、相机（记录照片/评价图片）、定位（探索）、分享。
- 离线/弱网（已决议）：一期支持体重与健康记录**本地暂存 → 联网自动同步**；其余功能在线使用。
- **推送依赖（新增）**：推送是 L2 生命线——iOS 需 APNs；Android 依赖厂商推送通道（账号/资质/可能费用）为**一期关键依赖**，随阶段二选型落实。
- **备案依赖（新增）**：App/小程序形态确定后立即启动工信部备案（上线前置，见 PRD §6）。

### 3.2 官网
- 产品介绍（四大模块）、品牌故事、帮助中心、法律条款。
- 各端入口引导（去 Web / 下载或打开移动端）。
- 精选资讯/活动展示用于 SEO；与用户端资讯的内容关系：官网做展示层，数据同源。
- **页脚合规信息（新增）**：ICP 备案号（链接工信部查询）、公安备案号、《用户协议》《隐私政策》《社区规范》《投诉举报与版权通道》入口。

### 3.3 管理端
- 仅桌面 Web 形态（第一期不做管理端移动端）。

### 3.4 用户端 Web
- 覆盖全部 C 端功能，与移动端数据实时一致。

## 4. 跨端一致性要求

- 账号与数据全端打通（同一账号、同一档案、提醒不重复不遗漏）。
- 品牌视觉统一；交互遵循各端平台习惯（Web 桌面模式 / 移动触控模式）。
- 邀请链接、分享卡片跨端可打开并正确回跳。
