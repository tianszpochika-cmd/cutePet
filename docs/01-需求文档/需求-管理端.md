# 需求文档 · 管理端（平台运营）

> 状态：已定稿（上线合规修订 v1.1） · 优先级：P0 · 期次：第一期 · 版本：v1.1

## 1. 概述

平台运营人员的工作台，支撑内容（含 UGC）、商品导购、探索数据、用户与家庭、数据治理的可持续运营。UGC 进 MVP 与探索全量使**审核治理成为一期核心能力**。

## 2. 功能需求

### 2.1 内容运营
- 文章：发布、编辑、下架、置顶、定时发布。
- **投稿审核**（对应 C7）：待审列表、通过/驳回（必填意见）、修改后重提的复审、批量操作。
- 分类与标签管理；首页推荐位/banner/专题配置（对应 C6）。
- 评论管理：删除、屏蔽、置顶；举报处理。

### 2.2 商品导购运营（方案 A，无交易）
- 商品库 CRUD、上下架、分类管理。
- 导购清单/评测的维护与商品关联管理。
- ❌ 不含：商家管理、订单、售后（方案 A 排除）。

### 2.3 探索运营（全量一期）
- POI 增删改、营业状态标记、属性标签维护。
- 用户纠错处理：待处理建议列表 → 采纳/驳回。
- 评价抽审与异常评价处理（配合 D5 防刷策略）。
- 遛宠路线审核（D6，先审后发）。
- 本地活动/领养信息发布与审核（D7）。

### 2.4 用户与家庭治理
- 用户查询、详情（登录/互动/投稿记录摘要）。
- 封禁/解封、投稿资格取消。
- 家庭共享相关投诉与纠纷处理（如越权访问举报）。

### 2.5 数据看板（第一期核心指标）
- 内容：发布量、审核队列与时长、消费量（浏览/互动）。
- 留存：建档数、提醒触发与完成、周活。
- 探索：POI 覆盖、评价/纠错量、导航点击。
- 导购：商品浏览/收藏。
- 指标口径需在设计阶段与运营对齐后定稿。
- **埋点采集需求（新增）**：看板指标对应端内埋点（浏览/点击/留存/转化），埋点方案随交互设计输出，并同步列入隐私政策收集清单。

### 2.6 消息触达管理
- 提醒/通知模板管理（对应 B5/H2）；发送记录与失败率查看。
- 第一期不做营销群发（商业化不做）。

### 2.7 平台治理与安全
- 审计日志：谁在何时做了审核/封禁/配置变更。
- 敏感内容与举报的统一处理队列。
- 高危操作二次确认（删除、封禁、批量下架）。

### 2.8 内容安全（上线合规新增） ⛔
- **机审层**：文字敏感词/模型过滤 + **图片审核**（文章封面、评价图、路线/活动图、头像——涉政/涉黄/涉暴）+ **账号信息审核**（昵称、头像、简介发布时校验）。
- **词库运维**：敏感词库增删改与版本记录，定期复审（权限点归入 system.settings 词库管理）。
- **疑似转人工**：机审命中疑似进复审队列，不直接处罚。
- **违规处置分级**：

| 等级 | 情形 | 处置 |
|------|------|------|
| L1 轻 | 广告灌水、轻微不当 | 删内容 + 提醒 |
| L2 中 | 重复违规、低俗、轻度违规 | 删内容 + 禁言 7 天 |
| L3 重 | 明显违规、导流诈骗 | 禁言 30 天 + 内容清理 |
| L4 严重 | 违法违规内容 | 永久封禁 + 证据留存 + 依法上报 |

- 累计升级：180 天内 L1×3 → L2；处置全量留痕，均可申诉（见《需求-平台规则与客服》）。

### 2.9 投诉举报与版权通知-删除（上线合规新增） ⛔
- **举报统一队列**（对象：文章/评论/评价/场所/路线/活动/用户）：普通举报 **≤48h** 处理，结果通知举报人。
- **版权投诉通道**：公示专用邮箱/表单；收到合格通知**立即下架**涉嫌内容并通知作者，作者可反通知申诉；全过程留痕（避风港机制）。
- 处理指标（举报量/时效/成立率）进数据看板。

## 3. 业务规则

- 所有审核操作留痕；驳回必填意见。
- 角色权限：编辑（内容）、审核员、POI 运营、管理员等角色的权限集（RBAC，设计阶段细化）。
- UGC 治理原则：**先审后发**为主（投稿、路线），评价**先发后审 + 抽审 + 举报**。

## 4. 非功能需求

- 仅授权内部人员访问；权限与操作全量审计。
- 审核队列 SLA（已决议）：目标 24h 内处理；超 24h 队列标红，超 48h 升级通知主管。
- **审核编制假设（新增）**：SLA 以编制到位为前提——按《冷启动运营计划》的 UGC 量测算人力与班次；吞吐上限与积压监控进看板。
- 后台性能与批量操作效率：运营体验要求，设计阶段细化。
