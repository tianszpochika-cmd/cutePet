# 需求 · 指标与验收口径

> 状态：评审中（口径已定义，产品效果待真实验证） · 版本：v1.0 · 更新日期：2026-09-22

## 1. 统计共同规则

- 自然日/周统一北京时间，周一为周起点；事件同时保留实际发生时间和平台接收时间。业务完成按服务端确认时间统计，离线记录的健康发生日期不倒灌为过去的活跃事件。
- PV 为有效页面打开次数，UV 为去重账号数；游客以匿名会话单列，不混入账号留存。登录后仅在已有告知与允许范围内关联本次来源，不跨设备猜测身份。
- 排除内部测试账号、演示数据、已确认自动化/刷量；显示排除数量与口径版本。治理后认定无效的事件可重算，历史报表标记重算日期。
- 同一业务动作的重试事件按业务动作编号去重；客户端展示事件按事件编号去重，不能仅按页面点击按钮计成功。
- 比例分母为零时显示“暂无样本”；每张率值同时显示分子、分母及观察窗。未成熟观察窗显示“观察中”，不按零记失败。
- 家庭、宠物、账号、待办、内容、报名是不同统计粒度。家庭成员分别计账号活跃，但同一个待办只计一次完成。
- 每日次日中午生成 T+1 报表，迟到事件在 7 天内自动重算；更晚到达须标记补算批次。报表不宣称精确实时。
- 不采集正文、健康记录详情、出生日期、手机号、精确位置到分析事件；使用受控标识及必要状态，收藏/报名等源业务数据与分析访问权限分开。

## 2. 一期指标字典

| 编号/链路 | 指标 | 分子 / 分母或计算方式 | 粒度与观察窗 |
|---|---|---|---|
| K01 / L1 | 注册后照护激活率 | 注册后 24 小时内拥有一份完成档案且启用至少一个计划的账号 / 已注册满 24 小时的新增目标账号 | 账号；受邀只读用户单列，不强制要求其建档 |
| K02 / L1 | 建档向导完成率 | 首次启动后 24 小时内完成至少一份档案的账号 / 启动向导且窗口成熟账号 | 账号；恢复草稿不重复计启动 |
| K03 / L2 | 有效照护周活 | 当周至少完成一次有效健康/体重记录、待办处理或有效记录更正的账号数 | 账号；仅浏览和推送打开不计照护活跃 |
| K04 / L2 | 到期待办完成率 | 到期后 72 小时内完成的待办 / 到期后已观察满 72 小时的待办 | 待办；提前完成也计完成；到期前取消排除，到期后取消/跳过仍在分母 |
| K05 / L2 | 按时完成率 | 不晚于计划到期时间完成的待办 / 同 K04 成熟分母 | 待办；与 K04 同时展示，不混淆宽限期 |
| K06 / L2 | 次周照护留存 | 激活所在周的下一自然周内有 K03 行为的账号 / 已经历完整下一周的激活账号 | 账号；按是否有该周到期待办分层 |
| K07 / L2 | 真实推送送达率 | 有渠道送达凭证的通知 / 渠道支持送达回执且实际尝试的通知 | 接收者×待办×通知种类；无回执单列未知，Mock 不入分母 |
| K08 / L2 | 提醒打开率 | 首次发送后 24 小时内点击对应通知的接收者待办数 / 发送窗口已满 24 小时且渠道接受的接收者待办数 | 首提醒和逾期提醒分别统计；不称为送达打开率 |
| K09 / L3 | 有效阅读率 | 可见累计≥30秒且正文滚动≥50%的文章访问会话 / 有效文章访问会话 | 每账号/游客会话×文章×自然日去重；短快讯可见≥5秒单列 |
| K10 / L4 | 创作者首次发布率 | 首次进入创作后7天内有审核发布内容的账号 / 窗口成熟的新创作账号 | 账号；文章/评测/清单分层 |
| K11 / L4、L8 | 审核通过率与时长 | 通过的版本 / 已作最终结论的版本；提交至最终结论的时长 P50/P90 | 内容版本；撤回不计通过率，单列撤回数；等待和审核中均计积压 |
| K12 / L5 | 导航发起率 | 查看详情后24小时内成功发起导航动作的账号会话 / 详情访问且窗口成熟账号会话 | 账号/游客会话×POI×日；无法确认唤起则计“导航点击”，不计到店 |
| K13 / L6 | 商品收藏转化 | 查看商品后24小时内新增有效收藏的账号 / 查看商品且窗口成熟的账号 | 账号×商品×日；取消后同日再藏不增加次数 |
| K14 / L6 | 收藏回访 | 首次收藏后第2–7天主动回到商品/关联评测的账号商品对 / 已观察满7天的首次收藏账号商品对 | 不推断购买；自动刷新不计主动回访 |
| K15 / L7 | 公开分享带来激活 | 带有效分享来源的访客登录/注册后7天内达到 K01 的账号 / 已观察满7天的来源关联注册账号 | 仅公开链接；采用注册前7天最近一次有效分享来源；不做奖励归因 |
| K16 / L9 | 家庭协作激活 | 首次共享后7天内至少两名成员对共享宠物产生有效写入或待办处理的家庭 / 首次共享窗口满7天且至少两名成员的家庭 | 家庭；只读加入率另列，不把只读家庭记为协作成功 |
| K17 / L11 | 活动报名转化 | 查看详情后24小时内有效报名的账号 / 报名开放且窗口成熟的详情访问账号 | 账号×活动；满员/截止访问单列；有效报名与累计成功分开 |
| K18 / L11 | 活动取消与通知处理 | 本人取消数/累计报名成功数；已创建通知/应通知报名者；失败未处理量 | 活动与报名；无核销故不输出到场率 |
| K19 / L8、L12 | 治理响应率 | 在对应 SLA 内完成响应/处理的工单 / 期限已到的有效工单 | 工单类型分层；版权特殊流程不得套普通举报时限 |

## 3. 事件清单与责任

所有事件至少含 event_id、发生/接收时间、统计主体、对象编号、环境（真实/模拟）、口径版本、来源端；下表属性仅保留必需业务结果。

| 事件族 | 必备事件 | 产生方 / 附加属性 |
|---|---|---|
| 认证及激活 | registration_completed、pet_wizard_started、pet_created、reminder_plan_enabled | 注册/建档/计划成功由业务端确认；带来源任务、是否受邀 |
| 照护 | care_record_saved、care_record_corrected、reminder_due、reminder_completed、reminder_skipped、reminder_cancelled | 业务端；待办、计划、宠物、家庭及处理账号受控编号，原定时间、确认时间、原因类别 |
| 通知 | notification_created、send_attempted、provider_accepted、delivery_confirmed、notification_opened、send_failed | 通知服务及真实回执/点击；渠道、接收者、尝试序号、结果，不带正文 |
| 内容 | content_viewed、reading_qualified、creation_started、revision_submitted、review_decided、content_published | 阅读客户端采集，提交/审核业务端；内容类型、版本、结论类别 |
| 探索导购 | poi_viewed、navigation_clicked、navigation_launched、product_viewed、favorite_added、favorite_removed | 客户端可观测导航与业务收藏分别采集；不采集用户精确轨迹 |
| 分享家庭 | public_share_opened、share_registration_linked、family_joined、pet_shared、member_permission_changed | 分享来源签名或合法来源标识、家庭/宠物受控编号；不记录邀请码明文 |
| 活动治理 | enrollment_created、enrollment_cancelled、activity_changed、activity_cancelled、case_created、case_resolved | 业务端；活动版本、原因类别、工单类型；不包含姓名电话/证据附件 |

- 业务负责人确认事件含义，开发负责人验证重试不重复，运营负责人按指标样例复算；没有真实数据前展示空态，不填“合理示例”冒充经营数据。
- 服务端成功事件是业务完成的依据；点击“保存”后失败不能计完成。浏览统计受浏览器阻断时标记覆盖率限制，不与业务完成率混为一谈。

## 4. 可复算样例（验收输入，不是真实经营结果）

| 场景 | 输入 | 预期 |
|---|---|---|
| 重试与家庭 | 同一待办甲成功，甲重试一次，乙再提交一次 | 完成待办1，关联新记录最多1；乙若无其他有效写入，不因此增加有效照护人数 |
| 成熟分母 | 到期且观察满72h共10条，其中提前取消1条、到期后取消1条、已完成6条（含按时4条）、跳过1条、未处理1条 | K04=6/9；K05=4/9；提前取消不入分母，另显示取消数2 |
| 无回执 | 真实通知10条：5条渠道支持回执且4条确认送达，另5条无回执；另有20条模拟 | K07=4/5，送达未知5；模拟20不计真实通知 |
| 无到店证据 | POI详情成熟会话8，导航点击3，可确认成功唤起2 | 导航点击率3/8、K12=2/8；不输出到店率 |
| 收藏反复开关 | 同用户同商品同日藏→取消→再藏，次日主动查看 | 新增收藏动作去重1，日末有效收藏1；进入相应回访观察窗 |
| 跨日离线 | 周日发生的健康记录周一联网确认 | 记录时间显示周日；K03计入周一所在周，不重复计入前周 |
| 审核改稿 | 线上v1，提交v2后撤回，提交v3驳回，再提交v4通过 | 通过率1/2；撤回1；v3驳回不撤销v1；v4通过后替换 |

## 5. 效果验证与停止条件

- 首发核心人群假设：有明确照护安排的养宠人和共同照护家庭；不是已经完成的用户研究结论。研究执行见 [用户调研](../03-研究资料/用户调研.md)。
- 首轮招募目标12–20人，其中至少4组共同照护家庭，实际招募数与退出原因如实记录；先做任务可用性，再做连续28天试用，低频提醒单独看60–90天成熟数据。
- 可用性试验暂定出口：关键任务无越权/丢数据；首次建档、首次投稿、活动报名和家庭协作各至少5次独立执行，≥80%无需主持人帮助；失败点修正后重测。此阈值为内部迭代标准，不是市场成功证明。
- 留存/收藏/导航的商业效果阈值在首轮基线后确定；当前没有基线，不虚构行业标准。样本不足或观察窗未满只能记“未验证”。
- 出现家庭越权、重复待办完成导致重复记录、错误活动信息继续报名、未审内容公开时暂停相关放量，修复并补证据后恢复；暂停放量不等于取消既定一期功能。
