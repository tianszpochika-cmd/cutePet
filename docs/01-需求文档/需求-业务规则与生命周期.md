# 需求 · 业务规则与生命周期

> 状态：评审中（授权补齐完成，待整体验收） · 版本：v1.0 · 更新日期：2026-09-22
>
> 本文为跨模块业务规则的唯一详细定义，编号 BR 用于设计、开发任务和验收追溯。依据负责人本轮“补齐文档”授权作出细项选择，保留六项已确认的一期范围。原审查报告为历史发现，不作为现行规则。

## 1. BR-01 · 核心任务与交付承诺

- 主任务：用户和家人准确记录宠物照护，知道谁已处理、还需做什么、下次何时处理。完成后可选择阅读资讯、探索场所、查看用品，不以继续浏览为完成条件。
- 进入产品的来源任务优先：读文章、接受家庭邀请、报名、写评价等登录后回原任务，不强制先建宠物档案。只有主动选择建档时进入向导。
- 一期功能全量范围保持不变；本地流程演示、真实外部能力验证、正式产品验收分别记录。模拟登录、通知、地图、审核不能抵销真实能力未交付。
- 移动端仍要求真实提醒触达；支持的运行环境、授权条件与限制应在注册后通知设置和创建提醒页可见。未获授权或环境不支持时，显示“仅站内提醒”，不能显示“已开启系统提醒”。
- 无推送渠道或用户拒绝通知时，保留全部记录功能和站内待办；不擅自改用短信/邮件营销。用户退出产品后能否触达必须由真实通道验证；正式能力不满足时阻断相应产品验收。
- 官网当前入口文案为“开始使用”“手机打开”，二维码打开移动端入口；只有可下载安装包已发布且验证可用时才显示对应下载按钮。

## 2. BR-02 · 提醒计划、待办与完成记录

### 2.1 两层业务对象

| 对象 | 状态 | 业务意义 |
|---|---|---|
| 提醒计划 | 草稿 / 启用 / 暂停 / 结束 | 宠物、类型、周期、时间、排期基准、渠道偏好；保留计划历史 |
| 本次待办 | 未到期 / 待处理 / 逾期 / 已完成 / 已跳过 / 已取消 | 归属一个计划，具有唯一编号、计划到期时间、实际处理时间和处理人 |

- 同一计划同时只保留一个未终结待办；“逾期”仍可处理，不是删除或失效。
- 启用计划即生成首个待办，到期变待处理；超过到期时间 72 小时变逾期，并对仍有权限且允许通知的接收者追加一次提醒。
- 本期结束才安排下期；逾期未处理不自动产生一串积压待办。界面显示“逾期未处理，后续安排等待本次处理”。
- 单次计划的待办完成或跳过后，计划结束；周期计划继续生成下期。暂停计划取消尚未终结待办并保留原因；恢复时由用户确认新的未来首期时间，不补发暂停期间通知。
- “关闭本次”改为“跳过本次”（必填简短原因，继续后续）；“关闭计划”改为“暂停此计划”。关闭同宠物同类型多个计划须逐条列出并确认，不能影响其他宠物。

### 2.2 排期规则

- 北京时间为一期业务时区。每 N 天：N 为 1–3650 的整数；默认以本期计划时间为基准，用户可选“实际完成日”。系统只执行用户设定，不推断医疗周期。
- 计划日基准：从本期到期时间按 N 天递增，取严格晚于当前操作时刻的首个时间；跨过的周期不补建待办，显示被跨过的周期数。
- 完成日基准：取关联照护记录的实际发生日期，加 N 天并沿用计划时刻；若仍不在未来，再按 N 天递增到未来。跳过时没有实际照护日期，按计划日基准排期。
- 每年：保持月日时分，不跟随完成日期漂移；2 月 29 日在非闰年落 2 月最后一天，创建页明确展示；下一年回到原月日。
- 用户手填“下次日期”优先于自动计算，并在完成确认中显示；下一期沿用原周期设置和新确认的到期时间。编辑周期只影响未终结待办，已完成历史不改写。
- 例：9 月 1 日 09:00 到期、每 30 天、9 月 5 日处理，计划日基准下期为 10 月 1 日，完成日基准且发生日为 9 月 5 日则为 10 月 5 日。

### 2.3 完成及记录一致性

- 疫苗/驱虫/用药/体检/复诊待办完成时，必须选择已有健康记录或填写对应记录；自定义待办可只填完成说明。已存在记录不得再次复制。
- 同次操作中记录有效保存与待办完成同时成立，任一失败均不显示完成成功。前端待同步只是本地草稿，不触发完成消息或下期排程。
- 同一待办只接受第一次有效完成；重试返回原结果。另一家人稍后提交时显示“已由某成员完成”，展示原结果，不再新增关联记录或下一期待办；其未提交输入仍可复制为独立记录，但须明确确认且不得再次完成该待办。
- 补录历史记录不会自动完成待办；用户显式选择待办后，界面展示记录日期与计划时间差并确认。
- 单独新增疫苗/驱虫记录时：有匹配活动计划则让用户选择关联、更新或新建，默认不另建重复计划；没有计划且填了未来日期才创建单次计划，周期由用户另行确认。
- 删除被待办引用的健康记录前说明影响，保留受限的关联审计摘要，完成历史标记“关联记录已删除”而不重新排期；更正记录不静默更改已经生成的下一期。
- 宠物归档/软删时暂停全部计划、取消未终结待办。恢复档案不自动恢复共享或推送；所有者确认共享对象及未来时间后逐项恢复。

### 2.4 通知生命周期

- 分别记录待办产生、通知创建、发送尝试、渠道接受、可确认送达、打开、完成。渠道没有送达回执时显示“送达未知”，不可当作送达成功。
- 每个待办、接收者、通知种类只生成一个站内通知；同一账号可在已授权设备触达，任何设备或成员完成后其余端读取统一结果。
- 推送前重新检查待办未终结、账号正常、共享仍有效、通知偏好允许；断网重试也必须检查，已完成/取消的待办不再补推。
- 待处理首提醒发送失败，在到期后的 24 小时内最多重试 3 次，间隔为首次失败后 1 分钟、15 分钟、2 小时；超过窗口只保留站内未处理状态。逾期追加提醒也使用同一 24 小时窗口。
- 免打扰仅推迟设备触达到时段结束，不推迟站内待办状态；超过发送窗口则不再推送，显示站内提示。全天免打扰等价于关闭系统推送。

## 3. BR-03 · 家庭、所有权与共享权限

### 3.1 关系与默认规则

- 每人最多一个家庭，每只宠物最多共享给一个家庭，且所有者必须是该家庭成员。个人宠物不因加入家庭而自动共享。
- 家庭有一个管理员（初始为创建者）；宠物有一个所有者（初始为建档者）；两者可不同。“记录作者”是留痕属性，不授予家庭管理权。
- 家庭邀请码有效期 7 天、可多次使用；家庭管理员可重置。加入页显示家庭名称与管理员，确认后加入；新成员对已共享宠物默认只读，不自动分享自己的宠物。
- 宠物所有者按“成员×宠物”授予只读或可管理，默认只读；修改立即生效。家庭管理员没有替其他所有者提升权限的能力。

### 3.2 权限矩阵

| 动作 | 宠物所有者 | 该宠物可管理成员 | 该宠物只读成员 | 家庭管理员身份额外权限 |
|---|---|---|---|---|
| 查看共享档案、健康、时间线 | 是 | 是 | 是 | 无额外宠物数据权限 |
| 编辑普通档案字段、新增健康记录 | 是 | 是 | 否 | 无 |
| 更正/删除健康记录 | 任意条目，说明原因并留痕 | 仅自己录入的条目，仍须有当前权限 | 否 | 无 |
| 创建/编辑提醒计划、完成/跳过待办 | 是 | 是 | 否 | 无 |
| 接收提醒 | 按本人偏好 | 按本人偏好 | 按本人偏好，可关闭 | 无 |
| 导出健康摘要或完整宠物数据 | 是，身份核验后 | 否 | 否 | 无 |
| 归档/删除/恢复/转移宠物 | 是 | 否 | 否 | 无 |
| 分享宠物到家庭、设置成员档位、解除共享 | 是 | 否 | 否 | 无 |
| 邀请/移除家庭成员、转交管理员、解散家庭 | 仅同时为家庭管理员时 | 同左 | 同左 | 是，但不能移走他人宠物所有权 |

- 非家庭成员不可访问共享档案。自己的收藏、草稿、私人联系方式、报名信息不因家庭关系自动共享。公开投稿按公开内容规则可见。
- 共享告知明确列出档案、记录、提醒和录入人，不使用“你的互动对所有家人可见”等宽泛表达。
- 家庭管理员不可将自己作为普通成员移除；需先转交管理员或解散家庭。

## 4. BR-04 · 转移、退出、注销与离线数据

### 4.1 双方确认的转移

- 家庭管理转交和宠物所有权转移是两个独立操作，入口分别在家庭管理和宠物资料的危险操作区。
- 仅能转给同家庭的正常且已完成适用同意流程的账号，双方分别进行手机号验证码核验；同一对象最多一个未决转移申请，申请有效期 24 小时。原所有者/管理员可撤销，接收者可拒绝；到期不变更。
- 宠物接收页展示档案摘要、有效提醒、现有共享授权及删除责任。接受时原所有者变为该宠物只读成员，其他可管理授权降为只读，新所有者之后可重新授权；仍保留当前家庭共享及历史录入人。
- 接受时再次核验双方资格、家庭关系和对象版本；期间任一人退出、注销、被封禁或档案删除，转移失效。成功前原所有者承担权限，成功后全端立即使用新所有者权限。
- 有未决转移时注销先撤销转移。转移不复制记录、不重置待办；已完成记录的处理人不变。

### 4.2 生命周期影响表

| 事件 | 档案与共享 | 待办与通知 | 用户反馈 |
|---|---|---|---|
| 普通成员退出/被移除 | 其自有宠物解除家庭共享，所有权保留；失去其他共享宠物访问；历史贡献保留 | 自有宠物计划继续仅对所有者；不再接收他人待办 | 说明失去哪些访问和保留哪些数据 |
| 解散家庭 | 所有宠物回到各自所有者私有，解除授权，不删除档案 | 所有者的计划继续，原成员触达取消 | 通知原成员，邀请失效 |
| 归档宠物 | 仅所有者操作；历史可在归档列表查询，解除共享 | 暂停计划、取消未终结待办 | 可恢复，需重新授权共享及启用计划 |
| 软删宠物 | 仅所有者操作；回收站保留 30×24 小时，其他成员不可见 | 同归档 | 所有者可恢复；期满删除关联业务数据 |
| 治理强制清除 | 普通回收站不可恢复；依法需要留存的治理证据隔离管理 | 取消未终结待办和触达 | 处置原因及申诉入口 |
| 申请账号注销 | 无论是否家庭管理员，都列出自有宠物、共享、活动、转移申请 | 冷静期停止本人推送，不取消其他人的有效待办 | 按下面注销规则处理 |

- 注销前：家庭管理员须完成管理转交或解散；自有共享宠物可选择双向转移或解除共享后随账号删除，**归档本身不等于转移**；有未结束活动的发布者须取消活动并通知报名者；未结束报名须取消。界面提供直接操作，不要求必须找到接收者。
- 确认后冷静期 15×24 小时；停止账号写操作、撤销普通会话。再次核验登录后显示“撤销注销/仅查看状态”，只有显式撤销才恢复账号，不把误登录自动当作撤销。
- 冷静期撤销不自动恢复已解除共享、已取消活动/报名或已撤销转移。期满删除自有档案及附件（不再追加 30 天软删期限）；别人宠物中的贡献保留并匿名化录入者标识。
- 已发布 UGC 默认匿名化保留；内容本身包含可识别个人信息时进入清理队列，不能仅删除作者名。公共页面、搜索、缓存与引用同步更新，审计/处置证据隔离保留，法定留存清单由法务确认。
- 账号数据导出含个人资料、自有宠物及记录、个人收藏/投稿/报名和同意记录；不包含他人宠物完整档案、他人报名名单或第三方私有资料。用户对他人宠物的贡献仅导出其自己提交的字段及脱敏对象编号。

### 4.3 离线与并发

- 离线仅允许创建体重/健康记录草稿，不允许离线修改权限、转移、完成待办、删除或报名。草稿关联当前账号及宠物，显示“尚未保存到平台”。
- 联网时逐条重新验证账号、宠物状态、当前授权和草稿唯一标识；同一草稿重试只保存一次。失权/删除时不写入服务端，也不自动改投其他账号/宠物；显示失败原因，清理共享档案缓存及待同步副本，仅保留无敏感内容的失败回执。
- 登出/换账号前告知未同步条数，可返回联网同步或确认清除；不得让下一个账号看到或提交前一个账号的草稿。
- 对在线编辑的同一版本冲突，展示旧值、当前值和本次修改；用户选择放弃或确认覆盖后才执行后写覆盖。自动同步不能静默覆盖已有记录。
- 权限撤销保证下一次联网鉴权后停止访问并清除受控缓存；不声称能远程收回已经合法保存的截图或静态导出。

## 5. BR-05 · 活动、发布者与领养

### 5.1 发布者身份

- 普通手机号验证用户可投稿活动/领养，先审后发；认证机构可直发普通活动，但仍经过内容安全检查。领养无论发布者类型均须人工审核。
- “我的→活动中心”向所有登录用户开放：我的报名、我发布的活动/领养、机构认证。此为用户端能力，不提供商家交易后台。
- 认证申请：机构名称、类型、联系人、联系电话及必要资质证明→运营核验→通过/驳回（附理由）/撤销；证明仅指定审核人员可见，公众只看机构名与认证状态。认证有效期一年，届满需复核；未续期按普通发布者权限处理，不自动隐藏已审核内容。
- 认证不等于平台担保。被撤销认证后取消直发权；涉嫌违规的现有内容另走处置流程。机构联系人变更重新验证，不向新联系人自动提供旧导出文件。

### 5.2 活动与报名状态

| 对象 | 状态及动作 |
|---|---|
| 活动版本 | 草稿→待审→已发布；已发布→修改待审（旧版保留且按下述规则暂停报名）→新版本；可取消，不可从已取消直接恢复 |
| 活动运行状态 | 未开放 / 报名中 / 已截止 / 进行中 / 已结束 / 已取消；满员为报名中的容量标识，取消释放后可再报名 |
| 报名 | 成功 / 本人取消 / 活动取消；一期不设待审核、候补、付费、核销或出席状态 |

- 发布必填标题、城市、详细地点、开始/结束时间、报名开放/截止时间、名额（正整数或不限）、组织者联系入口。开放≤截止≤开始<结束；报名开放不得早于活动结束前90天，默认取当前时间与该边界较晚者，避免联系人数据在活动前到期。无法满足此关系的活动不可开放报名；全用北京时间。
- 每账号每活动最多一个有效报名；姓名及电话本人确认，已验证手机号可预填但不默认勾选提供同意。成功时绑定活动版本、接收方身份、告知版本及同意时间。
- 服务端以确认顺序分配名额；最后一名只能一人成功。重复请求返回已有有效报名；取消后在截止前且有余位时可重新报名，形成新报名记录并沿用历史。
- 尚未开放或截止/满员/开始/取消后禁止新增报名；本人在结束前可取消，释放名额但超过截止不重新开放报名。结束后只能查询及请求处理个人信息。
- 成功凭证为不可猜测的本人查询编号，无门票、核销或付款含义；仅本人和有权组织者可查看。我的报名保留地点、时间、状态及变更历史。
- 组织者只访问自己活动的有效报名名单与必要联系方式；名单默认脱敏，查看完整联系方式须确认用途并留痕。普通组织者无批量导出；内部运营经授权可导出并记录用途、对象范围及操作者。
- 更改时间/地点/组织者/参与条件属于重大变更：保存修改稿后立即暂停新报名，原报名继续有效并显示“活动信息核实中”；通过后通知所有有效报名者并提供取消入口。驳回可放弃修改并恢复原报名条件；不得无提示替换。
- 名额可增加，降低不得小于有效报名人数；提前截止可直接执行并通知，延后截止须仍不晚于开始时间。取消活动即时停止报名、将有效报名转为活动取消、通知报名者，不等审核。
- 活动通知至少有站内消息，已同意且真实可用的系统通道再触达；变更未读可在我的报名持续看到。发送失败进入运营待办，组织者在已告知用途内人工联系，平台不能把“已入队”显示为“对方已收到”。
- 姓名/电话最多保留自提交起 90 天且在活动结束或取消后 30 天内清理，取较早者；有报名的活动不允许改期至最早一条报名的 90 天期限之后。期满保留去身份化统计及必要同意/治理凭证，通知组织者删除其在合法用途内另行保存的副本并留处理记录。

### 5.3 领养与场所评价

- 领养是独立信息类型：动物信息、所在城市、发布者、联系入口、无偿声明、审核记录；没有“立即报名”或报名凭证。发布者可标记已结束，游客可看公开信息，登录后联系；手机号使用单独公开确认，不复用私有账号手机号直接展示。
- 领养状态：草稿/待审/已发布/已结束/已下架；发布 30 天后需发布者确认仍有效，否则停止公开，重新确认也要检查当前审核与账号状态。
- 评价默认通过内容过滤后公开并计分；账号注册未满 7×24 小时、全三项五星且去空白正文少于 10 字、图片重复命中、疑似违规，任一命中则仅本人待审、通过后才公开计分。
- 同账号同场所每个自然日仅提交一条，设备每天最多五条（无法取得稳定设备标识时不得伪称已完成设备限制，转入风控能力验收项）。被拒绝后修改同一条不占新名额，不能通过删除后重发绕限。
- 场所总分为全部公开有效评价三项评分平均值的算术均值，展示一位小数；隐藏/下架/举报成立不计，恢复后重算。没有评价显示“暂无评分”，3.5 只用于排序先验值，不伪装用户评价。
- 距离得分为 max(0,1-直线距离/当前半径)，评分得分为均分/5；综合=0.6×距离得分+0.4×评分得分，分高在前，同分按距离、场所编号。无定位不展示虚假距离，城市列表按评分得分及场所编号排序。

## 6. BR-06 · 内容版本、创作及可信度

- 创作入口始终可见；无作品时显示首次创作空态。创作类型包括文章、商品评测、好物清单；清单为内容子类型，复用审核队列，类型可筛选。
- 清单必填标题、导语、1–30 件在架商品、每件推荐理由；支持排序、删项、保存草稿和预览。评测至少关联一件商品。
- 评测必填来源类型“实际测试/资料整理”。实际测试注明测试者、时间、方法及局限；资料整理注明可核查来源和查阅日期；利益关系声明必填“无/有（说明）”。不能把普通用户自测展示为“编辑部测试”。
- 健康科普须注明资料来源及更新时间，审核记录区分内容安全检查与专业内容复核；涉及诊疗用药的知识性内容没有合适复核人员时暂不发布，不用免责声明替代复核。
- 排名/TOP 清单须说明范围、评价维度和排序依据；无依据只发布普通有序清单，不显示排名主张。商品库排除兽药、处方类药品、处方粮及购买信息，这是本期平台品类决策；不从该决策推导外部法律结论。

### 6.1 发布与修改

- 每个公开对象有一个线上版本，可有一个修改草稿/待审版本。文章、评测、清单、路线及普通用户活动的公开字段修改均重新审核；待审期间继续显示原已通过版本，活动重大变更另按 BR-05 暂停报名。
- 审核针对提交时的固定版本。待审稿不可原位更改，先撤回再修改重提；通过时校验当前版本仍相同。驳回修改稿不影响旧版，首次驳回不产生公开版本。
- 运营直发者可以免人工审批发布自己的普通内容，但仍须安全检查、版本留痕及理由。编辑他人的 UGC 不继承直发权；以新版本走审核。领养及需要专业复核的健康内容不豁免对应复核。
- 作者可立即撤下自己的内容，终止未决审核；治理下架的内容不能靠保存恢复，只有相应审核/申诉处理后才能重新公开。
- 删除/下架传播到列表、搜索、专题、收藏、分享页和商品反向关联；公开链接保留“已不可用”状态，不暴露待审正文。评论回复的父项隐藏时隐藏其回复树，作者仍可查看处置结果。
- 商品普通下架保留历史卡片并标注已下架；违禁商品治理清除时所有引用去除敏感展示，仅留“该商品不可用”。清单商品全部不可用时不可新发布，已发布页保留文章解释与不可用提示。

### 6.2 退修、违规及治理

- 驳回原因分“内容质量/材料缺失”和“经人工确认的违规”；质量退修不暂停投稿。滚动 180 天内 3 次违规驳回（同一提交版本仅计一次）暂停投稿 7 天，可申诉；申诉撤销的记录剔除，恢复时已用于该次暂停的记录不重复触发。
- 投稿暂停、禁言和封禁是不同能力：暂停只禁新投稿；禁言限制投稿、评论、评价和公开活动/路线发布，仍可记录私人宠物数据；封禁拒绝一般业务操作，保留受限申诉及状态查询。
- 机审疑似只进入待审，不自动处罚。举报失败不等于恶意举报；只有人工确认滥用才可限频，并记录理由及申诉入口。
- 举报对象补齐商品/清单/报名隐私投诉；版权、申诉、一般客服各用独立工单状态和 SLA，不用“文章通过/驳回”替代所有工单动作。
- 普通举报/处置申诉 48 小时内反馈；投稿 24 小时目标、超过 48 小时升级主管。客服产品问题 48 小时内首次响应；版权按已审定专门流程处理。业务状态处理结果、后续行动、负责角色与通知结果均留痕。

## 7. BR-07 · 记录字段与健康摘要

| 字段 | 规则 |
|---|---|
| 体重/疫苗/驱虫/体检/就医发生日期 | 不晚于北京时间今天；未知历史日期可标记“日期不详”，不可伪造今天，体重曲线不接收无日期点 |
| 下次提醒日期时间 | 严格晚于创建/确认操作时刻，可为未来；不受发生日期上限约束 |
| 用药开始/结束 | 开始为已实际开始日期，不晚于今天；结束可为未来且不得早于开始；持续使用可不填结束，标注进行中 |
| 过敏 | 过敏原/反应必填，首次发现日期可不详；未解除的过敏作为长期信息，历史解除也保留记录 |
| 宠物生日 | 允许准确生日或估计年龄；不详不阻断建档，估计值明确标记 |
| 体重 | 正数 kg/斤；0.1–200kg 外二次确认，不硬拒绝异宠；与时间顺序前一有效点相比波动≥10%二次确认 |

- 曲线每条有效体重为一点；同一发生时刻多条不自动合并，日摘要取当日最后一条并可展开。补录按发生时间排序，编辑/删除后重算。
- 七日趋势以最新发生日 D 的体重对比 D-7 日之前或当天最近一点，最多回溯至 D-14；没有该区间基准显示“数据不足”，不插值伪造。变化率=(最新-基准)/基准；绝对值≥5%仅提示数值变化，不解释为疾病诊断。
- 摘要默认包含基本档案、全部仍有效过敏、当前用药、近 30 天健康事件和未来提醒；可选择近 90 天/全部事件。长期信息不受近期窗口过滤；使用者主动取消模块时在预览提示遗漏。
- 摘要为所有者核验后生成的静态图片，显示生成时间、所选窗口和缺项，不含主人手机号、机构联系人等非必要私人信息；附件默认不带入。普通共享成员无导出按钮。

## 8. BR-08 · 分享对象与回跳

| 对象 | 分享形式 | 游客落点与失效行为 |
|---|---|---|
| 已发布文章/评测/清单/路线/活动/商品 | 公开详情链接及封面卡 | 可读当前公开版，互动或报名时登录回原位；下架显示不可用 |
| 宠物健康摘要 | 所有者选择生成的静态图片 | 图片包含已选择信息；可附通用产品介绍二维码，不含实时私有详情链接 |
| 宠物时间线/实时健康记录 | 一期仅家庭内授权查看，不生成公共链接 | 外部链接须登录且有授权，否则显示无权限；不展示私有标题/照片 |
| 家庭邀请 | 7 天邀请链接 | 游客仅看家庭名称与管理员公开昵称，登录后确认加入；失效后不暴露档案 |

- 分享面板区分复制链接、保存图片和当前环境实际可用渠道。不可用渠道不显示成功；不承诺平台未提供的直接分享到指定应用能力。
- 回跳只允许平台内部合法对象目标，保存来源动作但涉及发布、报名、加入、删除等必须恢复确认页，不能登录后自动执行不可逆提交。点赞/收藏可自动续做并支持撤销。
- 一期分享指标衡量公开链接打开和后续激活；静态图片的实际传播次数不可观测，不计入裂变系数。邀请奖励、海报裂变运营仍为二期。

## 9. BR-09 · 年龄、监护人、账号与隐私控制

- 年龄判断采用自报完整出生年月日，以北京时间日期计算实际周岁；只存受限访问的年龄依据与确认记录，不公开生日。未知年龄不能默认成年，进入帮助入口。生日输入与真实监护关系的核验强度须经正式上线审查，短信核验本身不冒充法律身份认证。
- 未满 14 岁须监护人核验并同意专门规则；满 14 岁后再次登录提示本人确认相应协议，记录新同意，不静默解除未完成的治理限制。
- 监护人入口在登录页与帮助页独立可达；用已绑定监护手机号验证码进入受限控制页，只显示脱敏儿童账号及同意状态。撤回需再次确认，立即撤销儿童账号正常会话、停止新增处理和推送，提供数据处理请求与客服路径；不授予任意查看儿童私人内容的通用账号权限。
- 微信首次注册同样走手机号绑定、协议与年龄分支，不绕过儿童流程。手机号与微信绑定冲突时要求验证现有账号，不自动合并不同用户数据。
- 隐私总同意撤回进入受限状态，可查看规则、提出导出/删除请求、申诉与重新同意；拒绝非必要定位/通知不阻断档案等功能。首次不同意可进入不收集可选信息的游客浏览，不写“不同意则退出”。实际游客数据处理范围随正式隐私文案核验。
- 封禁/注销冷静期/监护同意撤回采用受限验证入口：短信或现有受限凭据只允许本人申诉、查询处置、查看规则及提出个人信息请求；不能用于正常写操作、读取他人数据或新注册绕过封禁。
- 申诉提交→待受理→处理中→支持/维持，结果可在受限入口查询并使用已验证联系渠道告知。一般客服与恢复原手机号的找回申请同样具有单号、进度及人员处理记录。

## 10. BR-10 · 变更、证据与复审

- 产品规则变更须同步模块需求、功能设计、页面规格、数据概念和验收用例；规则编号保持稳定，修订记入评审记录。
- 文档闭合与实际交付分别追踪；本轮仅完成规则定义。真实通道、法务文案/资质、冷启动预算与供给、用户假设仍须取得实际证据。
- 逐项场景与开发任务见 [闭环验收与交付门禁](../05-技术文档/闭环验收与交付门禁.md)，指标见 [需求-指标与验收口径](需求-指标与验收口径.md)。
