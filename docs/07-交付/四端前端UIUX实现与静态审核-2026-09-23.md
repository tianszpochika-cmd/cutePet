# 四端前端 UI/UX 实现与静态审核（2026-09-23）

> 状态：静态审核完成，运行与业务验收待执行 · 版本：v0.1 · 更新日期：2026-09-23

## 1. 本轮范围与证据

按官网 → 用户端 Web → 管理端 → 移动 H5 的顺序，把四份 UI/UX 设计稿落实到现有 Vue 前端，并修正静态审查中发现的回跳、路由、接口参数、权限说明与错误状态。四端复用品牌色：奶油底色、深色文字、装饰亮橘；白字主按钮使用深橘 `#B85111`。现有设计稿仍是**评审材料**，不是可用性或业务验收证据。

根据本轮要求，仅编辑源码和文档并做**静态逻辑审核**：核对路由目标和文件、生成客户端的方法名、响应判断、权限及成功状态、键盘焦点和部分响应式规则，执行 `git diff --check`。本轮**未运行构建、类型检查、自动测试、浏览器、服务、数据库或 Docker**。历史《状态表》中的纯逻辑测试数字属于 2026-09-22 快照，不能作为本次修改的测试结果。

| 端 | 本轮实现 | 当前边界 |

## 2. 静态审核结果

- 官网内链、Web 与管理端动态路由文件、移动端新详情路由和生成客户端方法名做了源码核对；本轮改动范围的 `git diff --check` 无空白错误。该检查不证明组件可编译或页面可运行。
- 公开读取与私人读取区分了加载、空数据和失败；不能核验的数据不再用虚构内容填充，也不把接口错误显示为“没有记录”。
- 管理端审核样例仅用来核对筛选、锁、版本、理由及批量确认条件，不改变状态；管理员身份和操作权限仍需服务端确认。
- 移动端记录仅在平台返回有效记录编号后显示成功。网络超时或回执不明时，页面要求先核对时间线，避免重复提交；待办与健康记录尚无原子完成契约，完成按钮不可用。
- 手机底栏使用统一线性图标与 `env(safe-area-inset-bottom)`；主要触控目标按至少 44px 设计。320/375/414px、键盘、缩放、减少动画和真机安全区**尚未实际走查**。

## 3. 必须继续处理的集成问题

| 编号 | 问题与影响 | 后续责任与所需结果 |
|---|---|---|
| F01 | 网关尚未把 Bearer 令牌可信地转换为宠物、内容、商品、探索、通知及管理服务要求的本人身份/权限；宠物服务仅读 `X-User-Id`，所以移动端取得令牌后仍无法经当前网关读取私有宠物数据。前端未伪造 `X-User-Id` 或 `X-Permissions` | 网关/IAM/各域：验签、身份与权限透传、逐对象授权，并以跨账号请求验证 |
| F02 | 短信仍有固定开发码，正式协议与隐私版本、未成年人独立监护核验尚未交付 | IAM/法务：真实通道与版本、完整年龄/监护回执后再开启登录 |
| F03 | 内容服务仍按“质量退修三次暂停”计算，违背 BR-06“质量退修不暂停；滚动 180 天三次人工确认违规才暂停” | 内容服务：修规则、存量状态、接口字段与测试；本轮仅纠正 Web/移动/管理前端文案 |
| F04 | 健康待办缺与有效记录关联并原子完成的读写回执；体重写入契约与提醒落单仍不完整 | 宠物服务/契约：补详情、原子处理、幂等及并发回执，随后开启两端完成操作 |
| F05 | 家庭接口缺成员清单和逐成员逐宠授权数据，转移候选/撤权与通知结果也未形成可核验闭环 | IAM/宠物/通知：补对象级权限、当前版本、转移与通知回执 |
| F06 | 投稿搜索命中缺稳定详情标识；投稿版本与审核详情不足；商品与其他内容收藏没有统一本人汇总 | 内容/商品/探索：补详情与本人聚合，前端再开放对应入口 |
| F07 | 匿名 `/pois/{id}` 详情响应已确认包含完整场所电话；领养联系方式还需审查。仅在页面隐藏不能防止接口泄露 | 探索服务：按公开范围脱敏/裁剪，再复核移动与 Web 展示 |
| F08 | 管理员真实登录、权限获取、审核锁、审计和指标聚合未联通；当前仅有公开列表与只读样例 | 管理/IAM/网关：服务端鉴权、完整队列与操作回执，再验证角色和跨人并发 |
| F09 | 账号导出缺独立核验，注销依赖、正式联系渠道、备案与公开部署入口待确认；移动离线草稿缺安全持久队列 | IAM/法务/部署/移动：分别给出安全契约、公开地址与端到端证据 |
| F10 | 官网资讯与活动栏目目前如实显示待接入，尚无公开列表到详情的完整前端链路；活动详情服务仅按 ID 读取，缺已发布状态校验 | 官网/内容/探索：接入只含已发布内容的公开列表与详情，核验撤稿/下架、错误与空态 |

这些问题同步登记在[已知问题清单](已知问题清单.md)。不能把页面已绘制、请求能发出或 HTTP 200 当作业务验收通过。
