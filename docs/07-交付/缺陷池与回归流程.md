# 缺陷池收敛流程 与 两轮回归方案

> 状态：v1.0 · 2026-09-22 · 任务 T12.1（流程）+ T12.2（两轮回归）——**执行归本地测试阶段；本机交付流程与工具口径**
> 关联：《闭环验收与交付门禁》§5 出口 · 状态表 E01–E08 · 手动矩阵/E2E 用例库

## 1. 缺陷池收敛流程（T12.1）

### 1.1 池子与字段（登记模板）

每条缺陷一行（建议 issue 表或 `docs/07-交付/缺陷池.csv`，本地阶段建立）：

| 字段 | 说明 |
|------|------|
| ID | DEF-001…（全局递增） |
| 来源 | E2E-Lx / 手动矩阵 / 性能清单 / 合规复测 / 负责人走查 / 用户反馈 |
| 端 | web / admin / site / mobile / service / docs |
| 标题 | 一句话现象 |
| 重现步骤 | 编号步骤 + 前置数据 |
| 期望 vs 实际 | 分列 |
| 级别 | **P0 阻断**（核心链不可用/数据错误/合规风险）· **P1 严重**（主流程受阻可绕）· **P2 一般**（体验/文案/边缘）· **P3 建议** |
| 归属 | 模块 Mx / 任务 Tx / 责任人 |
| 证据 | 截图/日志/接口返回（E 层） |
| 状态 | NEW → FIXING → FIXED → VERIFYING → CLOSED；REOPENED 回 FIXING |

### 1.2 收敛节奏（三步收敛）

1. **日清**：当日新缺陷全部入库定级；P0 24h 内出修复或明确阻塞原因。
2. **周结**：P1 清零计划滚动；P2/P3 由负责人决定本迭代修 or 记入「已知问题清单」延后（必须记归属与理由）。
3. **出口收敛**（对齐门禁 §5）：
   - P0 = 0 且两轮回归通过；
   - P1 = 0 或有负责人书面接受的规避方案；
   - P2/P3 全部在《已知问题清单》留痕（不得静默丢弃）；
   - 合规自查表 26 项全 ☑（C24–C26 硬阻塞除外——它们未解除则整个出口不成立）。

### 1.3 修复纪律

- 修复必须附：**回归用例 ID**（从 E2E/矩阵引用）+ **逻辑层新增断言**（若属规则类缺陷，本机可先行补 `*.test.ts`）；
- 状态流转只允许 `VERIFYING→CLOSED` 由**非修复人**执行（防自证）；
- REOPENED ≥2 次自动升级一级别。

## 2. 两轮回归方案（T12.2）

### 2.1 第一轮：全量回归（R1）

| 项 | 内容 |
|----|------|
| 范围 | E2E 用例库 28 条全跑（L1–L9 ×四端）+ 手动矩阵 28 行全表 + 每页四态补查 |
| 环境 | 本地测试阶段环境（9 服务 + 四端构建产物），对照 L/E 隔离清单替换全部 dev shim |
| 通过线 | 用例通过率 100%（失败即缺陷入库）；P0/P1 = 0 才允许进入 R2 |
| 证据 | 执行记录回填手动矩阵 ☐→☑ + E2E 运行报告归档（E 层证据） |

### 2.2 第二轮：聚焦回归（R2）

| 项 | 内容 |
|----|------|
| 触发 | R1 缺陷修复完毕后 |
| 范围 | ① R1 全部失败用例的重跑；② 按修复影响面扩散（改了 pet → 重跑 L2+L3+L7 关联）；③ 冒烟子集：E-L1-01 / E-L2-02 / E-L4-01 / E-L5-02 / E-L7-01 / E-L8-01 / E-L9-02（七条跨链冒烟）；④ 性能 P1/P2/P5 复测；⑤ 合规自查 ✅ 类抽测 10 项 |
| 通过线 | 冒烟 100%、回归失败=0、性能达标、抽测 10/10 |
| 证据 | R2 报告 + 缺陷池全 CLOSED/留痕 + 负责人签字（验收走查清单） |

### 2.3 回退出口 → 发布门禁

```
R1 全量通过 → 修复 → R2 聚焦通过 → 缺陷池收敛达标 → 验收走查签字（T12.4）
→ 合规硬阻塞 C24–C26 解除 → 方可进入发布流程（备案/资质以负责人提供为准）
```

任一环节不达标：回到缺陷池，不允许「带 P0/P1 发布」或「跳过第二轮」。
