# 文档规范

> 所有 `docs/` 下文档须遵循本规范。

## 1. 文档头部

每份文档必须包含：

```markdown
# 标题
> 状态：草稿 / 评审中 / 已定稿 · 版本：vX.X · 更新日期：YYYY-MM-DD
```

## 2. 状态定义

| 状态 | 含义 |
|------|------|
| 草稿 | 编写中，内容可能大幅变动 |
| 评审中 | 提交评审，等待结论 |
| 已定稿 | 评审通过，作为开发依据 |
| 已废弃 | 被新版本取代，移入 `archive/` |

## 3. 编写原则

- 用「作为…我可以…以便…」表述用户故事。
- 每个待定决策用 `待定/待确认` 标注，并尽量写在「待决事项」表中。
- 不在需求/设计文档中写技术选型（框架、数据库等），相关内容留到阶段二。
- 结论优先：先写结论，再写论据。

## 4. 变更流程

1. 修改文档 → 更新版本号与日期
2. 涉及跨模块影响 → 记录到 `评审记录.md`
3. 重大变更 → 重新评审

## 5. 目录约定

- `00-项目概述`：项目级文档
- `01-需求文档`：回答「做什么」
- `02-设计文档`：回答「怎么呈现/怎么运转」
- `03-研究资料`：依据与输入
- `04-规范与模板`：过程规范
