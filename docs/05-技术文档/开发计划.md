# 开发计划（Development Plan）

> 状态：评审中（闭环修订完成） · 版本：v1.1 · 更新日期：2026-09-22
>
> 与 `开发任务规划.md` 的分工：**规划 = 做什么、怎么验收（What/How）**；**本计划 = 何时做、谁来做、什么节奏（When/Who）**。
> 基线：选型 v1.1（与 cloudstudy 全栈对齐）+ §0 DoD + §5 无 Bug 出口准则（不可降低）。

## 1. 计划概述

- **目标**：在开发机上从零交付——本地一键可测、需求 In-Scope 100% 可用、通过 §5 全部出口准则的 cutePet 四端系统。
- **执行环境**：开发机（cloudstudy 环境已就绪，见规划 §1.1）；设计机仅用于文档与评审。
- **执行模型（默认假设，可评审调整）**：

| 项 | 默认 | 说明 |
|----|------|------|
| 执行者 | **Agent 主执行 + 负责人每日/隔日评审**（纯 Agent 项目） | 任务粒度 = 规划中 T 编号任务，一次领一个 |
| 代码评审 | 负责人按里程碑评审 + 关键合入抽查 | 设计/需求问题走评审记录 |
| 回归观察窗 | **7 天**（Agent 高速迭代下 14 天收益低；可改 14） | §5 出口准则第 5 条 |
| 设计复审 | 受本轮修订影响的文档在 **W1–W2 并行**完成，不阻塞 M0–M1 | 品牌名/Logo 决策最迟 W2 末 |

**节奏约定**
- 每日：Agent 任务流水（看板状态流转）；负责人隔日评审一次。
- 每周五：**周演示**（按当周 Gate 的链路现场走查）+ `git tag m{N}`。
- 任何一周结束主分支必须可运行（门禁强制）。
- 范围变更：只进 `评审记录.md`，由负责人批准后调整排期，**不改 DoD**。
