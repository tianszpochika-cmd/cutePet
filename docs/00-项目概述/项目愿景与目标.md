# 项目愿景与目标

> 状态：评审中（产品假设与验证计划已补齐） · 版本：v1.0 · 更新日期：2026-09-22

## 1. 愿景与主价值

帮助养宠人及共同照护家庭准确记录照护、协同处理待办、查到可信养宠信息并发现附近资源。首要价值是减少漏记与重复处理，明确下一次安排；不以增加无目的浏览时长为首要目标。

## 2. 首发用户假设

| 人群 | 待验证任务 | 一期服务 |
|---|---|---|
| 主要：有固定照护安排的养宠人 | 回忆上次照护、制定下次提醒、就医出示摘要 | 档案/记录/计划/摘要 |
| 主要：共同照护家庭 | 知道谁已处理，避免重复，交接后权限准确 | 共享、待办协作、转移退出 |
| 次要：外出与选购用户 | 找到合适场所，理解产品差异 | 探索导航、活动、评测清单 |
| 内容/活动供给者 | 发布有用内容和活动，获得明确审核反馈 | 创作、活动中心与数据 |
| 内部运营 | 维护资料质量、及时响应投诉和变更 | 治理工作台、数据与失败待办 |

以上为设计假设，不是已完成调研的结论。机构只提供活动/领养信息，一期无商家交易平台。

## 3. 成功判断

第一层验证任务可完成且不越权/不重复记录；第二层验证照护周活、次周留存及家庭协作激活；第三层验证资讯、探索、用品是否为同一人群带来附加价值。具体K01–K19、分母/观察窗/样例见 [指标与验收口径](../01-需求文档/需求-指标与验收口径.md)。

零真实基线时不填写增长承诺。先做12–20人的招募目标及28天试用，低频提醒观察60–90天；样本不足明确未验证，不宣布商业成功。

## 4. 范围与执行原则

保留六项已确认范围：纯内容导购、UGC、无商业化、家庭共享、移动全量、探索全量。第一版不引入订单/支付/售后、邀请奖励、个性化推荐和休眠营销；角色退出、活动生命周期和内容修改属于既有功能闭环。

分链开发与验证：L2/L9先验证，随后内容和活动，最后跨模块效果；顺序不减少一期承诺。文档闭合、本地实现、真实通道和正式上线分别记录。

## 5. 决策与外部输入

产品负责人确认业务方向与复审出口；开发负责人提供真实能力证据；运营负责人确认首发城市、供给、排班和预算；专业人员审查正式条款及资质。具体人员姓名和预算不得由文档虚构，未到位项进入上线门禁。
