## 2. 主导航与入口规则

已决议的底部四栏是 **首页 / 资讯 / 探索 / 我的**，用品从首页“逛好物”进入，宠物从首页和“我的”进入。四栏根页面分别落在[首页](index.html#home)、[资讯](资讯探索与用品.html#news)、[探索](资讯探索与用品.html#explore)、[我的](index.html#me)。二级页进入后保留来源任务，返回时应恢复原列表位置。

当前应用的[四栏定义](../../../apps/mobile/src/domain/mobile.ts)却是“首页 / 宠物 / 探索 / 我的”，与[信息架构 §3](../信息架构.md)及本组设计稿不一致。后续应由产品复核并统一实现，不能把现有代码的导航当成已决议变更。

游客可以浏览公开内容；记录、收藏、投稿、报名、加入家庭等写操作经登录闸门后回原任务。报名、投稿、加入、待办完成等动作回到**确认页**，不能登录后自动提交。登录也不强迫先建宠物档案。

## 5. 必须贯穿每页的状态

1. **照护可信**：提醒计划与本次待办分层；逾期超过 72 小时仍可处理，不自动堆积下一期。疫苗、驱虫、用药、体检和复诊待办完成时须关联已有或新建相应健康记录，只有记录与待办一起保存成功才呈现完成。家人抢先完成时展示原处理人与结果，保留用户输入，不重复写入。
2. **弱网和离线**：一期只允许体重及健康记录作为本机草稿。草稿写“尚未保存到平台”，不播放完成动效，不生成下一期待办。恢复网络后逐条重验账号、宠物、授权和草稿编号；失权时清理敏感副本。登出或换号前明确待同步数量及“返回同步/确认清除”。
3. **家庭与隐私**：加入家庭不自动共享个人宠物。新成员默认只读；家庭管理员不自动获得宠物数据权限。“可管理”成员只能更正自己录入的记录；健康摘要与完整导出、归档、删除、转移仅宠物所有者。无权深链不先展示私有标题或图片。
4. **通知真实状态**：站内待办产生、通知创建、渠道接受、可确认送达、打开、完成分开表达。未获系统通知授权或目标环境不支持时写“仅站内提醒”，不能写“已开启系统提醒”；无送达回执写“送达未知”。用户退出后离站触达需要真实通道验证。
5. **深链与回跳**：提醒落到相应宠物的提醒/待办；审核结果落投稿状态；家庭邀请落加入告知；公开分享落当前公开版，私有健康摘要仅静态图片。登录后回原位，但报名、投稿、加入与完成待办仍由本人再次确认。
6. **敏感健康数据**：过敏与当前用药属于长期信息，不因近期窗口而漏掉；体重变化提示数值，不下疾病诊断。摘要只由所有者核验后生成静态快照，标明生成时刻、时间窗和被主动省略的模块，不含手机号或实时私有链接。

## 6. 当前应用路由与设计边界

当前 [apps/mobile/src/router.ts](../../../apps/mobile/src/router.ts)以 H5 hash 路由提供 /login、/、/quick-record、/pets、/explore、/news、/write、/family、/family/invite、/family/join、/me、/settings、/settings/notify、/settings/delete、/me/sync、/todos/:id/confirm、/pets/:id/share、/pets/:id/transfer、/pets/recycle 等入口。路由存在不等于每项业务已贯通；例如家庭邀请/加入共用 FamilyMobile.vue，授权/转移/回收站共用示意组件 XPagesMobile.vue。

以下路由目前明确**重定向到其他页作为占位**：/goods、/goods/:id、/explore/poi/:id、/events、/news/:slug、/pets/new、/pets/:id、/messages、/me/favorites、/me/activity-center。设计稿有相应场景也不能据此认为应用细页已经接通。当前移动应用的快速记录、首页数据、待办完成、同步与家庭处理仍有本地样本/模拟分支，不能用页面展示证明真实保存、推送、定位、审核或账号授权。

**评审出口**：本组五份 HTML 可评审品牌一致性、信息层级、触控与局部状态；仍需按[移动端 UX 规格](../移动端设计-UX与逐屏规格.md)补完上表细页，并在目标设备走查 320/375/414 宽度、系统字号、屏幕阅读器、键盘、安全区、减少动画、弱网/断网与手势返回。真实短信、微信登录、推送离站送达、地图定位、记录原子保存、跨端同步、权限撤回及数据导出须分别以运行证据验收，不能由原型或静态检查代替。
