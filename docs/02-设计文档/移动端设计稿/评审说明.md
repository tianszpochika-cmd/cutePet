## 2. 首页层级与视觉取舍

**照护任务 → 当前宠物 → 一步记录 → 家人协作 → 需要时的发现。** 项目首先要减少漏记与重复处理，明确下一次安排；首页不把资讯和商品放在本次照护之前。底部导航按已决议的四项「首页 / 资讯 / 探索 / 我的」。宠物详情从首页宠物卡、快速记录或“我的宠物”进入；用品由首页进入，不单占 Tab。

以 375px 为基准并兼容 320px，页边距和卡片内距 16px。单手主操作尽量放在屏幕下部：主按钮 48px，输入框 48px，触控目标至少 44×44px；输入文字用 16px，避免 iOS 聚焦时意外放大。二级流程保留可见返回，不把侧滑作为唯一退出方式。底栏、动作条与弹层为安全区留白；系统减少动画时停止位移与循环效果。移动 H5 可借鉴原生手势语言，但原生推送、触感反馈和系统相册能力须另行验证。

卡片用白底、细描边和 16px 圆角区分层级；高频任务页不照搬官网的大面积投影。品牌亮橘 #FF7A2F 用于插画与装饰；白字主按钮采用深橘 #B85111 改善对比度。资讯粉、探索绿、用品蓝与家庭紫辅助辨认领域，状态仍须同时写明文字。图标使用同族圆头线性 SVG，不在底栏混用 emoji。

## 3. 六条评审任务脚本

1. **首次进入**：从游客页选择“照护待办”或“家庭邀请” → 查看登录、协议、验证码及年龄分支 → 核对返回原任务的位置。加入家庭、完成待办等返回后仍需重新确认；建档不是登录后的强制步骤。
2. **本次照护**：从首页待办进入 → 区分计划与本次待办 → 关联已有健康记录或新增记录 → 预览下一期 → 对照平台确认、家人已抢先完成与失败保留输入。打开或滑动卡片都不能直接算完成。
3. **弱网记录**：快速记录体重或健康事项 → 检查字段与体重变化达到 10% 时的二次确认 → 切换本地待同步、冲突和失权状态。离线草稿不能显示“已保存”；失权或换账号须清理敏感副本。
4. **家庭协作**：邀请前看共享范围 → 受邀人确认加入 → 落到家庭概况（可能暂无共享宠物） → 宠物所有者按成员、按宠物给只读或可管理权限 → 切换只读和撤权视角。家庭管理员不自动拥有他人宠物的数据权。
5. **出门与阅读**：浏览公开资讯；探索页拒绝定位时手选城市并可看列表；场所评价和纠错显示审核或工单状态；用品只给参数、评测与清单参考，无购物车和支付。
6. **创作与收藏**：从“我的”进入三种创作类型和五类收藏，查看一篇示例投稿的退修原因。质量退修与违规处罚分开说明；当前只评审入口、分类空态及结果信息，编辑器与重提过程仍待深化。

健康摘要仅由宠物所有者核验后生成**静态快照**，标注生成时刻、窗口和缺项，不包含手机号、附件或实时私有档案链接。提醒计划与本次待办分开展示；完成健康待办时，记录保存和待办状态必须同时由平台确认。系统通知不可用时应明示「仅站内提醒」。

## 4. 页面状态与可用性

| 状态 | 要让用户理解的事 |
|---|---|
| 首次空态 | 没有宠物、记录、共享宠物或消息的原因与一个明确下一步 |
| 加载与弱网 | 保留当前对象、表单和筛选；仅允许的本地草稿可离线暂存 |
| 本地待同步 | 不写“已保存/照护完成”；显示账号边界、重试及离开或换号前处理 |
| 冲突与失权 | 家人已处理时展示平台当前结果，不重复生成记录或下一期待办；撤权后拒绝读取并清理敏感副本 |
| 提交失败 | 保留可恢复的输入，查询真实平台结果后再重试，避免重复提交 |
| 成功与通知 | 服务端确认后才更新记录、处理人和下一次安排；通知请求、渠道接受与可确认送达分开 |
| 深链与返回 | 推送回相应宠物与待办，家庭邀请回告知与确认；Tab 和二级页保留原位置 |

手势都有可见按钮替代，弹层关闭后焦点回触发点，错误与异步反馈应供辅助技术读取。正式评审建议在 320、375、414px，以及文字放大、安全区、软键盘和减少动画条件下走查；静态稿不能代替真机验证。

## 5. 当前移动 H5 与目标设计的差距

移动应用已有页面和路由，但编写本稿时多处仍是本地演示或重定向占位。当时 apps/mobile/src/domain/mobile.ts 底栏是「首页 / 宠物 / 探索 / 我的」，而设计文档已决议「首页 / 资讯 / 探索 / 我的」；MobileLayout.vue 在浏览器端给底部内边距固定 34px，可能覆盖实际安全区；Login.vue 的年龄分支链接没有对应路由；router.ts 中建档、宠物详情、商品与场所详情、消息等仍重定向到其他页面。Home.vue、TodoX01.vue 和 SyncMobile.vue 使用本地样例；QuickRecord.vue 本地校验后直接显示“已保存/已自动排期”，与真实结果边界不符。

这些是设计评审时的差距；随后已修改应用源码，但静态设计预览仍不能证明真实身份、服务端授权、跨账号同步、系统通知、实际保存或业务验收。依[状态表](../../05-技术文档/状态表.md)与[双端验收及 LE 未完成清单](../../07-交付/双端验收与LE未完成清单.md)分别核对开发状态与运行证据。
