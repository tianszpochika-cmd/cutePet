# 功能设计 · 闭环页面与状态

> 状态：评审中（闭环修订完成） · 版本：v1.0 · 更新日期：2026-09-22
>
> 行为依据：[业务规则与生命周期](../01-需求文档/需求-业务规则与生命周期.md)。原移动 #1–57 编号保留；下列 X 编号是补充页面或复用表单状态，不再以固定“57屏”推定功能完整。Web 使用对应页面/抽屉，用户端业务权限一致。

## 1. 入口与逐页闭环

| 编号/能力 | 入口与结构 | 提交/返回/异常 |
|---|---|---|
| X01 待办完成确认 | 提醒卡→选择已有记录/新增健康记录→发生日期及下次计划预览→确认 | 成功显示处理人/实际记录/下一次；失败留输入；家人已处理显示最新结果，不再次写入 |
| X02 计划详情与历史 | 宠物提醒Tab→计划列表→本次待办、周期、排期基准、历史执行 | 编辑只影响未完成；暂停/跳过明确区分；恢复必须确认未来时间 |
| X03 共享授权 | 宠物详情→共享管理→当前家庭、成员×只读/可管理 | 所有者核验操作；其他成员只看自己的权限；变更通知受影响成员 |
| X04 所有权转移 | 宠物危险区→同家庭接收者→影响清单→核验→发送 | 24h待接受，可撤销；接收消息→核验→确认共享重置；失败不变更原所有权 |
| X05 家庭管理员转交 | 家庭管理→管理员转交→成员选择→双方确认 | 与宠物转移分离；待接受时原管理员仍有效；退出冲突使申请失效 |
| X06 归档与回收站 | 我的宠物筛选→归档/回收站→历史详情、剩余恢复时间 | 仅所有者可恢复；恢复成功引导重新共享/启用提醒，不自动执行 |
| X07 同步结果 | 记录草稿标记/我的→待同步记录 | 显示每条待同步、失败、成功；失权清理受控副本，保留脱敏失败提示；登出前给返回同步/清除选择 |
| X08 活动中心 | 我的→活动中心→我的报名/我发布的/机构认证 | 所有登录用户可进入；无活动时显示“发布活动/领养”，无报名时浏览活动 |
| X09 发布活动 | 活动中心→活动/领养类型→动态字段→预览→提交 | 活动校验开放/截止/开始/结束及90天保存边界、名额；普通投稿待审、机构安全检查后直发；领养统一待审 |
| X10 我的报名详情 | 活动中心报名列表/成功页/通知 | 查询编号、当前时间地点、变更历史、状态、取消按钮；满员/截止不可新报名；取消前说明后果 |
| X11 活动管理与名单 | 我发布的→活动详情→编辑/截止/取消/报名名单 | 列表只见本人活动；实名字段默认脱敏、查看留痕；无普通用户导出按钮；取消通知进度可查 |
| X12 机构认证 | 活动中心→认证状态→申请材料/结果/续期 | 待核验、驳回修改、已认证、到期/撤销；仅显示本人申请材料，不公开附件 |
| X13 清单编辑 | 创作中心→新建→好物清单 | 标题导语、商品搜索/选择、拖动或按钮排序、理由、来源/利益声明→预览→保存/提交；上下架变化提交前再校验 |
| X14 内容修改版本 | 我的投稿→已发布内容→修改 | 顶部“线上vN/修改稿vN+1”，对比预览，撤回待审再编辑；通过后替换，驳回旧版保留 |
| X15 受限账号服务 | 登录/封禁页/帮助→核验→申诉、查询、规则、信息请求 | 只能执行受限动作；不转到普通个人中心；结果可查，不依赖恢复账号 |
| X16 监护人控制 | 登录页“监护人服务”/帮助→绑定手机号核验 | 脱敏关联儿童账号→同意状态→撤回确认；无关联不泄露账号存在性，可走人工帮助 |

## 2. 已有页面需要执行的共同状态

- #3/#4 手机号与微信首次注册均进入协议及实际周岁判断；#5 输入完整出生日期；#6 展示专门规则和监护人核验。未同意首次隐私可进入受限游客浏览，不加载可选分析/定位等能力。
- #7 首页宠物卡、待办条优先；无待办不制造紧急感；保存健康事件后回到实际记录结果，只有体重事件更新曲线。推荐资讯以次级入口呈现。
- #31 家庭视角按 BR-03 逐动作显示权限，不能用“可管理=全功能”；只读不得出现可提交的编辑/摘要导出入口。无权限深链统一为拒绝页，不先渲染私有数据。
- #32 记录表单按发生日期、计划日期、用药日期分开校验；离线显示未同步而非“已完成”；冲突页可放弃或再次确认覆盖，不自动覆盖。
- #34 列表区分计划与待办，展示“已完成”实例历史；“逾期”有记录完成/跳过按钮；系统推送未就绪明确写“仅站内提醒”。
- #35 摘要显示长期过敏/当前用药模块与时间窗，预览时说明静态快照和缺项；只有所有者可生成；分享面板不生成私有实时链接。
- #38 家庭页展示管理员和每只宠物所有者；新成员默认只读。只属于家庭不意味着对个人未共享宠物有访问权。
- #40 加入页明确共享范围，展示用户自己宠物仍私有；不得声称收藏/私有互动自动对家人开放。
- #41 创作主页永久保留入口，有文章/评测/清单类型，草稿箱/投稿/数据共用对象列表；#42 根据类型增加关联商品、来源证据、利益关系和专业复核提示。
- #45 宫格包含宠物/家庭/创作/收藏/消息/活动中心；创作无作品时显示引导，未登录统一回跳。
- #53 注销列出所有者和家庭管理员两个维度的依赖、活动与报名，提供转移/解除共享/解散/取消的实际入口。冷静期登录为明确撤销确认页。
- #56 封禁页保留申诉和状态查询；期满只恢复相应处罚能力，不能解除另一个仍生效的处罚。
- #28 活动与领养共用阅读组件但行为分开：活动报名/查询报名；领养联系/举报，无报名按钮。

## 3. 管理端补充闭环

| 工作台 | 类型/字段 | 操作与权限 |
|---|---|---|
| 内容审核 | 文章/评测/清单及版本号、差异、来源材料、旧版链接 | review.article；审核仅对当前提交版本生效；明确质量退修与违规 |
| 路线/活动 | 版本差异、时间地点变更、有效报名量 | route.approve / activity.manage；重大变更通过后跟踪通知结果 |
| 机构认证 | 申请材料、核验记录、有效期、变更历史 | activity.manage 处理申请；主管复核授予/撤销直发资格，记录操作者 |
| 报名数据 | 活动、组织者、有效报名、告知凭证、清理期限 | activity.manage 仅在业务范围内查看；导出另需 activity.export；下载有有效期和审计 |
| 投诉/申诉/客服 | 工单类型、对象、受理人、SLA、证据、结果 | 举报/版权/一般客服用 report.handle，申诉用 appeal.handle；不能用内容发布按钮处理工单 |
| 家庭纠纷 | 家庭管理员、宠物所有者、授权及变更证据 | family.dispute；不因接到投诉就代替所有者转移宠物，处理依据与通知必须留痕 |
| 运行异常 | 失败通知、数据清理失败、未完成专业复核、账号清理 | 各业务域有待办列表，主管查看逾期升级；不得仅展示后台任务“已运行” |

- 保留现有32个权限点，通过对象归属、业务域和审批规则补充约束；拥有权限点不代表可读取任意用户私人数据。
- 治理员查看涉及健康的私有证据必须由工单绑定最小范围、说明用途并留痕；普通运营页不开放健康档案浏览。

## 4. 交互验收方法

每个 X 场景及其复用页需检查：正确身份从可见入口到达、字段校验、提交中防重、业务成功结果、失败保留/清理、返回原任务、权限变更后拒绝、跨端一致。新增编号表示逻辑页面状态，不强制独立路由，也不得借组件复用省略入口或状态。

Web 与移动端均执行用户场景；管理端执行操作与审核，官网执行公开分享/不可用/入口引导。视觉与动效继承既有规范；业务成功前不得播放“完成照护”动效。
