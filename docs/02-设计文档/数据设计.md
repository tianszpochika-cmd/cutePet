# 设计文档 · 数据设计（概念层）

> 状态：评审中 · 版本：v1.1 · 更新日期：2026-09-22
>
> ⚠️ 本文档只做**业务概念与实体关系**设计，不涉及数据库选型、表结构等技术架构。

## 1. 核心实体（草案）

- **用户**：账号信息、角色、养宠标签
- **家庭组**：组名、创建者、成员（用户）、邀请（码/链接、有效期）
- **宠物**：品种、年龄、体重记录集、健康记录集
- **健康记录**：疫苗、驱虫、体检、就医、用药
- **提醒**：类型、周期、状态
- **内容**：文章、分类、标签、收藏、审核状态
- **场所（POI）**：类型、位置、设施、评价
- **商品**：分类、规格、导购清单
- **评价/互动**：点赞、评论、分享

## 2. 实体关系（草案）

```
用户 1—N 宠物（所有权）
用户 N—1 家庭组（成员，一人限一个家庭）；家庭组 1—1 创建者
家庭组 N—N 宠物（共享，含权限档位：可管理/只读）
用户 1—N 收藏(内容/商品/清单/场所/路线)
宠物 1—N 健康记录
宠物 1—N 提醒
内容 N—1 分类；内容 N—N 标签；内容 1—N 审核记录
商品 N—N 内容（评测关联）；清单 N—N 商品
场所 1—N 评价；场所 1—N 纠错工单；用户 1—N 评价
路线/活动 1—N 审核记录；活动 1—N 报名
用户 1—N 操作审计（管理端）
```

## 3. 关键数据口径（草案）

- 体重曲线数据点（已定稿）：时间戳 + 数值 + 单位（存储统一 kg，展示可换算斤）
- 探索「附近」口径（已定稿）：直线距离，默认半径 5km，可切 10/20km
- 资讯推荐依据（已定稿）：一期无个性化 —— 运营精选置顶 + 近 7 天互动热度排序

## 4. 数据合规

- 个人信息最小化收集；健康档案默认仅本人+家庭共享成员可见；注销 15 天冷静期后删除/匿名化；数据导出（JSON）为一期能力。
- 具体合规条款与法务文案：外部依赖（法务出具）。
