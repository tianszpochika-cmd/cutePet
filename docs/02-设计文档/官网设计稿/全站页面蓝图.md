# cutePet 官网全站页面蓝图

> 状态：设计方案，待评审 · 版本：v0.1 · 日期：2026-09-23
> 范围：把计划中的官网路由归并为六类页面模板，供首页视觉方向确定后逐页设计。本文**不表示这些路由已经实现、接入真实内容或通过发布验收**。

本蓝图依据[官网页面架构](../官网设计-页面架构.md)、[官网 UX 与逐页规格](../官网设计-UX与页面规格.md)和[项目愿景](../../00-项目概述/项目愿景与目标.md)整理。当前首页独立预览见 [index.html](index.html)；现有应用代码中的官网路由与下表规划不同，开发前须逐项核对 `apps/site/src/router.ts`，不能把设计路径当成已经可访问的地址。

## 1. 六类模板与路由归属

| 模板 | 计划路由 | 从首页进入的位置 | 主要任务 |
|---|---|---|---|
| 首页 | `/` | 品牌标识、全站返回首页 | 讲清照护记录、下一次安排和家庭协作，并分流到四大能力及使用入口 |
| 能力详情 | `/products`、`/products/pet-manager`、`/products/news`、`/products/explore`、`/products/supplies`、`/features/family` | 顶部「产品」、首页四大能力卡、家庭共享区 | 解释各能力适用的任务、操作范围和规则 |
| 场景 | `/solutions`、`/solutions/beginner`、`/solutions/multi-pet`、`/solutions/travel` | 顶部「场景」、首页「一天的使用」与「更多场景」 | 让访客从实际养宠情境理解跨模块使用路径 |
| 内容与活动 | `/journal`、`/journal/:slug`、`/events`、`/events/:id`、`/search`、`/c/:slug` | 顶部「资讯」「活动」、首页相关能力与场景卡 | 阅读已公开内容、发现活动、搜索和承接合规分享 |
| 支持与法律 | `/about`、`/careers`、`/contact`、`/help`、`/help/:slug`、`/legal/terms`、`/legal/privacy`、`/legal/community`、`/legal/children`、`/legal/report`、`/404` | 顶部「关于」「帮助」、页脚规则链接、错误页回退 | 说明品牌与规则，提供帮助、申诉及联系渠道 |
| 使用入口 | `/download` | 顶部与首页双 CTA、各模板页尾 CTA | 根据设备和发布状态，引导到已核验的 Web 或手机入口 |

表内共覆盖页面架构所列的 27 个主要路由，以及 `/404` 和 `/c/:slug` 两个补充模板。`/:slug`、`/:id` 表示模板实例；页面数量取决于真实已发布内容。品牌三页并入「支持与法律」模板组，是为了统一可信信息和页脚路径，并非把品牌介绍当成法律文件。

## 2. 全站导航和内容层级

建议桌面导航按「产品｜场景｜资讯｜活动｜关于｜帮助」组织，并保留「打开 Web」「手机打开」两个明确入口；手机导航使用可关闭的抽屉。首页四张能力卡分别进入相应能力页，家庭共享区进入 `/features/family`；「更多场景」卡应进入对应场景或能力，不让不同文案全部落到同一个区块。所有栏目页以面包屑返回上级，并在页尾提供适合当前任务的使用入口。

```text
首页 /
├─ 产品总览 /products ─ 四个能力详情 /products/*
│  └─ 家庭共享 /features/family
├─ 场景总览 /solutions ─ 新手 / 多宠 / 带宠出行
├─ 资讯 /journal ─ 已发布文章详情 /journal/:slug
├─ 活动 /events ─ 活动详情 /events/:id
├─ 搜索 /search 与专题 /c/:slug
├─ 关于 /about · 招聘 /careers · 联系 /contact
├─ 帮助 /help ─ 帮助详情 /help/:slug · 法律五页 /legal/*
└─ 使用入口 /download ─ 已核验的用户端 Web / 手机入口
```

官网承担公开介绍与阅读。建档、修改记录、处理提醒、互动和活动报名应进入用户端，在登录、权限及同意校验后完成；官网 CTA 不能让人误以为点击即完成写操作或报名。运营工作台属于内部入口，不进入面向养宠人的主要导航。

## 3. 各模板的页面规格

### A. 首页 `/`

**信息层级**：首屏一句核心价值与 Web/手机双入口 →「上次有记录、下次有安排、家人有同步」价值条 → 四大能力 → 一天的照护故事 → 家庭共享 → 资讯/出行/用品补充场景 → 常见问题 → 使用入口与合规页脚。首页先讲照护连续性，再讲其它服务；移动版保持同样的阅读顺序。

**主 CTA**：「打开 Web」「手机打开」，统一进入 `/download` 对应端的说明或已核验入口。次 CTA 进入 `/products` 和 `/features/family`。若入口尚未可用，明确显示准备状态，不提供看似可用的安装按钮。

**空态与真实性**：没有可核验数字、用户评价、媒体或合作授权时，隐藏相应模块；没有真实已发布文章或活动时，展示静态能力介绍，不填虚构卡片。宠物插画、手机画面和故事数据标为设计示意。首页预览的视觉完成度不代表运行验收或用户效果已经验证。

### B. 能力详情 `/products*` 与 `/features/family`

**信息层级**：`/products` 先比较「宠物管理、资讯、探索、用品」四个用户能力，每张卡给出任务、关键能力和详情链接。四个详情页共用「任务与适用对象 → 能力说明 → 界面示意 → 四步使用流程 → 边界/FAQ → 相关能力」骨架；模块内容分别突出照护档案与提醒、七频道与创作、附近场所与路线活动、商品资料与评测清单。

家庭共享页单独深入解释邀请与加入、共享范围、所有者/可管理/只读的逐动作权限、默认只读、未共享宠物保持私有，以及处理人和转移/退出规则。健康摘要仅由所有者核验导出；公开页不展示实时私有档案链接。

**主 CTA**：「开始记录」「阅读资讯」「探索附近」「查看用品参考」按能力进入用户端相应位置；家庭页使用「了解如何邀请家人」。所有 CTA 须先核验目标端、登录回跳和实际可用状态，不能让官网承担写入动作。产品总览也提供通向相应详情页的阅读型 CTA。

**空态与真实性**：没有已核准截图时使用标明示意的界面模型；用品页不展示虚构购买价、库存、购买外链或站内交易。评测可来自实际测试或资料整理，不能统称「实测」；上线内容应标来源、证据和利益关系。地图底图与定位能力在持证服务接入前只以示意呈现。功能数和健康记录类别若文档口径未统一，避免在营销文案中写死数量。

### C. 场景 `/solutions*`

**信息层级**：总览页按「日常照护、新手养宠、多宠家庭、带宠出行」介绍可选择的路径；三个详情页分别用「情境问题 → 可以执行的步骤 → 对应产品能力 → 示例时间线 → 相关文章/FAQ」组织。场景页解释组合使用，不强制用户完成照护后再刷资讯或购物。

**主 CTA**：新手页去建档与帮助，多宠页去档案/家庭共享，出行页去探索场所与路线；次 CTA 转到相关能力详情。不要把导航、浏览或查看活动写成已经到店、已经报名。

**空态与真实性**：没有城市供给、可公开路线或授权文章时保留任务说明及「当前城市暂无内容」状态，并给出城市切换或返回入口。人物、宠物和一天的时间线均是演示情境，不作为真实访谈或用户见证。日常饮食/喂食量记录属于后续范围，当前场景稿不把它写作一期已确定能力。

### D. 内容与活动 `/journal*`、`/events*`、`/search`、`/c/:slug`

**信息层级**：资讯列表为频道、搜索、已发布文章卡和分页；文章详情为标题/作者/时间、正文、来源、相关推荐与适当的健康免责声明。活动列表为城市、类型、日期、地点和状态；活动详情为信息、主办方、报名条件与告知，再给出进入用户端的动作。`/search` 聚合资讯、帮助和产品，保持分类清晰。`/c/:slug` 为受控专题模板，展示来源、发布时间、正文模块与回官网/用户端入口。

**主 CTA**：文章用「在用户端收藏/互动」，活动用「前往用户端确认报名」；领养信息只提供联系与举报，不提供领养报名或交易按钮。搜索结果分别进入本来源的详情页。分享进入用户端时带安全回跳地址，不直接开放外部任意跳转。

**空态与真实性**：列表只展示当前仍可公开的已发布内容；草稿、驳回、下架、删除不能继续以正常卡片展示。失效分享页说明不可用原因，并提供安全返回入口。活动无数据时用真实空态，不虚构城市、名额或报名人数。涉及疾病和用药的内容固定注明科普性质与遵医嘱。UGC 图片、主办方标识、用户评价和排行必须有来源及使用授权；专题不能开放任意 HTML。

### E. 支持与法律 `/about`、`/careers`、`/contact`、`/help*`、`/legal/*`、`/404`

**信息层级**：关于页介绍经负责人确认的品牌理念及团队信息；招聘页展示真实在招岗位，空岗时直说；联系页优先给出正式可用的支持、商务和举报通道，再提供表单。帮助中心以账号、档案、内容、探索与活动、隐私与合规分组，详情页提供步骤和后续求助。法律五页统一为标题、版本/日期、锚点目录、正文与联系出口；投诉举报页突出举报与版权通知、处理流程。404 告知路径不存在，并提供首页、产品和帮助入口。

**主 CTA**：帮助页为「查看步骤/联系客服或申诉」；联系页为「提交问题」；法律页为「返回使用场景/联系支持」，注册时须能直达对应正式条款。404 主 CTA 返回首页。

**空态与真实性**：没有职位、团队或媒体素材时显示空态或隐藏，不填虚构人员和合作方。正式品牌、邮箱、备案号与条款尚未定稿时，设计稿标为待定；正式站不能以占位文本承担法律告知。联系表单只有在服务端确实接收并生成可追踪结果后才显示「已收到」，失败时保留填写内容并允许重试。帮助搜索无结果时推荐真实相关条目。

### F. 使用入口 `/download`

**信息层级**：先解释「在电脑上使用」和「在手机上使用」，再根据已发布能力给出真实入口、设备要求、版本与更新信息，最后是常见问题及隐私/帮助链接。页面名称可保留既有路由，但文案应随分发方式调整：只有 Web 与移动 H5 时，以「打开使用」为主。

**主 CTA**：Web 打开已核验的用户端地址；手机打开已核验的 H5 地址或深链。若将来确有可安装包，取得发布渠道、版本和签名校验后才展示下载与二维码。用户进入登录后仍须按原任务确认记录或报名。

**空态与真实性**：入口未准备好时显示「准备中」与可用替代路径，不能连接 `localhost`、空链接或未经验证的商店/安装地址；二维码必须由真实目标地址生成。版本、更新日期、渠道和校验值只写已验证的信息。不得把站内消息或 H5 提醒描述为已接入厂商推送。

## 4. 跨模板交付约束

- **可达与反馈**：每个视觉上可点击的元素须有明确目的地或操作结果。导航、弹层、菜单、分页、筛选、表单应能用键盘完成；焦点可见，移动点按目标至少 44×44，关闭抽屉后焦点回到触发按钮。
- **响应式**：桌面可用双栏与分区导航；窄屏按单列阅读顺序呈现，地图、权限表和长目录需有可理解的移动版。无动画时内容仍可读，系统选择减少动画时停止循环和自动轮播。
- **内容来源**：公开内容与用户端最终应使用同一已发布版本，并同步下架/删除状态；当前源码中的示例文章、活动和产品信息不能作为真实上线供给。
- **阶段标签**：设计稿、代码实现、本地运行验证、真实通道、正式发布分别记录。品牌、法律、备案、地图与短信/通知等外部依赖未核验前，不在官网文案中宣称完成。
