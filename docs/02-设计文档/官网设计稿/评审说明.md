# cutePet 官网新版 UI/UX 稿 · 评审说明

> 状态：评审中 · 版本：v0.3 · 更新日期：2026-09-23

> 实现进展：本稿保留设计评审内容；2026-09-23 的源码回填与静态审核见文末第 10 节。

## 1. 评审结论与范围

本轮先评审**官网首页与两类关键内页**的视觉与使用路径。[首页视觉预览](index.html)、[产品能力内页](产品能力.html)与[使用场景内页](使用场景.html)用于讨论版式、层级、文案和交互意图；[全站页面蓝图](全站页面蓝图.md)整理了其余页面模板和导航关系。这些都是设计稿，不代表官网全部页面、真实内容接入或发布验收完成。后续栏目页沿用评审通过的视觉方向，再按既有[页面架构](../官网设计-页面架构.md)和[逐页规格](../官网设计-UX与页面规格.md)展开。

预览方式：在本机浏览器打开上述三个 `.html` 文件，可查看桌面与窄屏响应式版式，并操作能力弹层、场景切换、移动菜单和常见问题；[桌面首屏布局截图](官网-首页-桌面预览.png)可用于快速评审。页面是独立设计文件，不依赖项目服务启动；截图用于看布局，交互和最新色彩以 HTML 文件为准。

首页应让第一次到访的养宠人迅速理解：cutePet 帮助记录照护、减少家人重复处理，并明确下一次安排；资讯、附近探索和用品参考围绕这一核心任务展开。预览稿的首屏双按钮先跳至页尾 Web/移动选择卡；选择卡解释入口状态，正式地址待运行验收和发布准备后接入。

本稿沿用[视觉设计总纲](../视觉设计.md)中的「可爱、温暖、可信」、暖橘与奶油色、模块色和无障碍标准。`cutePet` 仍是工作名，爪印标识仍是占位，不作为品牌定稿。

按钮上的白字使用较深的暖橘 `#B85111`（对白约 4.97:1）；原品牌橘 `#FF7A2F` 继续用于插画和装饰。现有视觉总纲的主按钮色与白字对比不足，正式组件令牌需在评审时一并统一。

## 2. 目标用户与阅读任务

| 用户 | 初次到访时想确认的事 | 首页应给出的答案 |
|---|---|---|
| 有固定照护安排的养宠人 | 上次做了什么、下次何时做，能否方便记录 | 建档、记录、提醒、健康摘要组成连续照护路径 |
| 共同照护的家人 | 谁已经处理，自己能看什么、能改什么 | 家庭共享区解释协作价值与权限边界 |
| 外出与选购用户 | 哪里适合带宠、如何参考用品信息 | 探索和用品模块给出清晰入口，并注明用品是内容导购 |
| 首次了解产品的访客 | 产品是否可信、现在能否使用 | 说明 Web/移动入口的当前状态，以及内容、隐私与规则边界 |

这些是项目当前的**设计假设**，并非已经完成用户调研或验证后的用户画像。官网面向普通养宠人与家庭；运营工作台和内部技术结构不占首页主叙事。

## 3. 首页信息架构

```text
官网首页
├─ 首屏：一句核心价值 + 两个指向页尾选择卡的入口锚点
├─ 价值条：上次照护有记录 / 下一件事有安排 / 一家人有同步
├─ 四大能力：管理 / 资讯 / 探索 / 用品
├─ 一天的照护故事：早晨看安排 → 白天留健康记录 → 傍晚家人接力
├─ 家庭共享：避免重复、明确权限与交接
├─ 更多场景：养宠知识 / 带宠出门 / 用品参考的静态能力入口
├─ 常见问题：家庭权限 / 官网职责 / 用品交易边界
├─ 使用入口：Web / 手机选择卡，当前仅说明入口状态
└─ 页脚：帮助、联系、规则与资质信息
```

全站结构仍以[官网页面架构](../官网设计-页面架构.md)为依据。当前预览稿从首页可进入产品能力和使用场景两份内页；首页能力卡和更多场景卡打开对应功能说明弹层，首屏双按钮跳到页尾 Web/手机选择卡，选择卡点击后提示正式地址尚未接入。这些反馈均属于设计预览；正式站点需将栏目和使用入口接到已验证的实际地址。本轮稿件**不等于**页面架构所列栏目页全部完成。

## 4. 首页模块顺序与内容责任

| 顺序 | 模块 | 用户在这里获得什么 | 内容与状态要求 |
|---:|---|---|---|
| 1 | 顶部导航与 Hero | 在首屏读懂「记录照护、家人协作、安排下一次」；知道可从电脑或手机开始 | 一条主标题、一段短说明、Web 与手机两个入口锚点，分别跳至页尾对应选择卡；宠物形象为设计示意，不冒充真实用户宠物 |
| 2 | 三项价值说明 | 快速扫到「上次照护有记录、下一件事有安排、一家人有同步」 | 使用定性说明；未配置可信数据时不展示用户数、场所数等数字 |
| 3 | 四大能力 | 快速比较管理、资讯、探索、用品各解决什么问题 | 四块使用各自模块色；每块给出一个任务和一个详情入口，用品明确「纯内容导购，无交易」 |
| 4 | 一天的照护故事 | 看见同一件照护任务如何在一天里连续推进 | 按「早晨看安排 → 白天留健康记录 → 傍晚家人接力」三步切换；手机屏幕是交互示意，不伪装成真实账户数据；探索不放在这条三步主线中 |
| 5 | 家庭共享 | 理解共同照护如何避免重复、权限如何区分 | 说明可管理与只读边界，不展示私人健康资料或声称公开实时分享 |
| 6 | 更多场景 | 知道日常照护之外还有养宠知识、带宠出门与用品参考 | 当前为三张静态能力入口卡，打开对应能力说明弹层；因缺少真实已发布文章和活动，不展示文章卡或活动卡 |
| 7 | 常见问题 | 理解家庭权限、官网职责与一期无交易边界 | 可展开的问答应保持简短，回答与当前需求规则一致 |
| 8 | 页尾使用选择 | 分辨电脑 Web 与移动 H5 的使用方式 | 两张选择卡与首屏锚点对应；当前点击后提示入口为示意，不跳到未经验证的地址，也不展示安装包或二维码 |
| 9 | 页脚 | 找到帮助、规则与资质信息状态 | 正式条款、联系方式和备案号待核实，不将占位文本伪装为已生效信息 |

用户口碑与媒体报道暂不作为固定模块。取得可核验的授权、原文和出处后，再按既有逐页规格补入；没有素材时整块隐藏。

## 5. 关键用户路径

**首次访问 → 了解核心价值 → 比较四种能力 → 理解家庭协作 → 开始使用**

1. 访客到达首页，首屏标题与短说明在约 10 秒内交代主要价值；两个按钮分别滚动到页尾 Web 与手机选择卡。
2. 访客向下看到四大能力，每块只回答「能帮我做什么」；点击「了解更多」先在预览稿的弹层中阅读能力说明。
3. 三步故事把核心照护任务串成一天：早晨看安排、白天留健康记录、傍晚家人接力。探索、资讯与用品在后面的「更多场景」中补充展示。
4. 家庭共享区解释成员协作和权限差异，引导有共同照护需求的人进一步了解。
5. 访客在页尾比较 Web 与移动 H5。当前选择卡点击后仅告知正式地址尚未接入；待地址验证后再改为真实进入用户端。用户端的注册、建档、报名等写操作遵守原有登录与权限流程；官网不直接代替这些流程。

当前预览没有文章详情和活动详情；待真实已发布内容接入后，从这些内容进入的访客应能通过相关能力和使用入口回到上述路径。分享链接失效、内容下架时应给出不可用说明和安全返回入口。

## 6. 桌面与移动交互

| 项目 | 桌面 | 移动 |
|---|---|---|
| 导航 | 顶部吸顶导航带轻微毛玻璃；各项跳至首页对应区块 | 导航收起为可打开、关闭的抽屉；选择栏目后关闭抽屉并进入对应区块 |
| Hero | 文案与宠物主视觉双栏；两个按钮分别跳到页尾 Web 与手机选择卡 | 单列，先文案和行动，后插画；两个入口锚点仍各有明确去向 |
| 能力卡 | 2×2 网格；悬停轻抬升；点击按钮打开对应能力说明弹层 | 单列或适配宽度的双列；每张卡保留可点按的详情按钮 |
| 三步故事 | 用步骤标签、下一步按钮及键盘左右方向键手动切换；当前稿件不自动轮播 | 步骤控件保持可点按，手机示意画面随选择更新 |
| 常见问题 | 点击问题标题展开答案 | 使用原生可展开问答，点按和键盘均可操作 |
| 动效 | 入场和装饰微动帮助识别层级，不妨碍阅读与点击 | 降低装饰运动；触屏不使用鼠标视差 |

交互元素均需键盘可达、有可见焦点；触控目标不小于 44×44。每页仅一个 H1，图片提供替代文本，装饰图标从辅助技术中隐藏。系统选择减少动画时，停止循环、视差和自动轮播，仅保留不超过 100ms 的淡入。无脚本或动画失败时正文仍应可见。

## 7. 空状态与内容真实性边界

| 情况 | 稿件与落地处理 |
|---|---|
| 用户数、POI 数、文章数缺少可核验来源 | 隐藏信任数字，不填示例增长值 |
| 精选文章或活动没有已发布内容 | 当前预览用「更多场景」三张静态能力卡代替资讯流和活动列表；后续接入时只使用仍可公开的已发布内容，不用未审核、已下架或虚构内容 |
| 口碑、媒体 Logo、合作机构缺少授权 | 整块隐藏，不使用虚构评价、头像或机构标识 |
| Web/移动正式地址、安装包、二维码或深链尚不可用 | Hero 锚点只跳到页尾选择卡，选择卡点击后给出示意说明；不提供无效下载按钮或指向占位地址的二维码 |
| 品牌、联系方式、法律条款、备案信息未定 | 在评审稿中标注待定；发布前取得正式内容与核验结果 |
| 外部内容加载失败或分享失效 | 给出原因、重试或返回入口，不留下空白卡片或假成功状态 |

官网不展示私有宠物档案、实时健康摘要或未经授权的 UGC 图片。健康信息只作产品能力介绍，不给出医疗效果保证。用品为评测与清单等内容参考，一期没有购买、支付和售后流程。界面中的插画、产品示意屏和场景数据必须能被识别为**设计示意**；视觉完成度不能作为真实业务数据、用户认可或正式上线的证据。

## 9. 评审检查点

- 不阅读内部技术说明，首次访问者能否说出产品主要帮他完成的照护任务？
- 「管理、资讯、探索、用品」四块的职责和入口是否清晰？家庭共享的协作与权限是否说清？
- 从首页到开始使用是否有连续路径？所有看起来可点击的元素是否有明确结果？
- 375px 手机宽度、键盘操作、200% 缩放和减少动画条件下，内容是否仍能被完整理解？
- 所有数字、评价、内容、下载与规则信息是否有真实来源或清楚标注为待定？

## 10. 2026-09-23 实现回填

官网源码已按本稿的暖色视觉、照护主线和四项能力入口调整首页及内页，统一窄屏导航、焦点和减少动画处理。示例案例、活动、联系和分享结果已从产品页面移除；Web/H5 入口仅在正式 HTTPS 地址配置并标记核验后呈现。设计预览中的姓名、数字和视觉素材仍是评审示意。

本轮仅完成源码与静态逻辑审核，尚未运行构建、浏览器和真机，也未完成真实内容、法务、域名及可用性验收。详见[四端前端实现与静态审核](../../07-交付/四端前端UIUX实现与静态审核-2026-09-23.md)。
